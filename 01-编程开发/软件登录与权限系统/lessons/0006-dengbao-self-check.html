回看走完的路——第 1 课的桌面版五环节已全部覆盖：凭据提交与登录窗口（第 3 课）、校验与存储（第 2 课）、进程内会话（第 3 课）、权限检查（第 4、5 课）、审计（第 5 课）。知识阶段结束，现在轮到验收：你的使命是「能对照国标说清做到什么程度才算合格」——这一课做这件事。

等保三级「身份鉴别」四条，逐条对号

GB/T 22239-2019 三级系统「安全计算环境 → 身份鉴别」（8.1.4.1）四条要求，每条都通向课程里的一课（官方全文，以下为要点转述，测评以原文与测评机构口径为准）：

条款（转述）课程对应
a) 登录用户身份标识唯一，鉴别信息有复杂度要求并定期更换第 2 课。复杂度按 NIST 落地为「长度 + 黑名单」；「定期更换」见下方专题
b) 登录失败处理：结束会话、限制非法登录次数、超时自动退出第 3 课：失败锁定 + 无操作锁屏——一字不差的对应
c) 远程管理时防止鉴别信息在网络传输中被窃听多机连库形态对应「应用与数据库间的传输」；单机形态无此环节（诚实清单见下）
d) 两种或以上鉴别技术组合，且至少一种使用密码技术桌面形态多数达不到双因素——自查时如实标注差距；确有硬要求的岗位再配 USB Key/动态口令等第二因素
「定期更换密码」：国标与 NIST 打架怎么办 这是整门课标准冲突最尖锐的一处：等保条款仍写着「定期更换」，而 NIST 800-63B-4 明确不再推荐强制定期换密（只增加用户痛苦）。务实做法：测评按条款执行（设较长周期作为测评项），同时留一份沟通记录说明依据 NIST 的理由与补偿措施（黑名单 + 高熵要求）。测评机构对这一条口径不一，白纸黑字的记录在任何一方都占理。

访问控制与安全审计控制点（要点）

  • 访问控制：由授权主体配置访问控制策略、默认账户重命名或删除、多余/过期账户及时清除、授予所需权限最小化——第 4 课的矩阵评审和默认拒绝就是它的应用层答案。
  • 安全审计：审计覆盖每个用户；记录包含日期时间、用户、事件类型及结果；审计记录受保护、免受未预期的删除修改覆盖；《网络安全法》第 21 条要求日志留存不少于六个月。桌面形态的对应做法：审计表只增不删（不给任何角色「清空」入口）、多机连库时放中央库离开本机、定期导出归档。

诚实清单：本课程没有覆盖的

等保测评评的是整个系统，不止应用层。以下几块不在本课程范围内，自查时如实标注「待补」：

  • 传输加密：多机连库形态下应用与数据库之间、远程接入链路的 TLS——单机形态无此环节。
  • 主机与数据库层加固：操作系统账号、补丁、数据库自带审计——等保有整章要求，属运维域。
  • 备份与恢复：备份文件的访问控制与加密。

验收工具：桌面版自查单

六课内容已压缩成可打印的桌面安全自查单：A 凭据存储、B 登录窗口、C 密码策略、D 会话与凭据保护、E 授权控制、F 审计留存，每项标注依据与自查方法。自查规则只有一条：每个「不符合」当场写成差距清单（编号 + 现状 + 依据 + 整改方向）——清单写完，你的改造 backlog 就有了，使命里「做一次自查并输出差距清单」同步达成。

结课作业：交出你家的差距清单

  1. 跑完自查单：打印 桌面安全自查单，对照你家软件逐项核对并留证据（截图/代码位置/实验结果）。
  2. 写差距清单：按「编号 + 现状 + 依据 + 整改方向 + 期限」格式，每个不符合项一行。第一次自查落在 5–8 个不符合项是正常起点。
  3. 带回复盘：把差距清单带回来，一起排整改优先级（建议排序：密码明文/快哈希最先、审计缺失其次、界面权限再次、策略类最后）。
  4. 更新使命：MISSION 里四条成功标准逐条自评「能做 / 勉强 / 还差」——还差的那些就是答疑或加课的方向。

结课寄语——六课从「认证 ≠ 授权」走到「差距清单」，你的桌面登录权限体系已经有一套可辩护的标准依据。继续精进的三个去处：Information Security Stack Exchange（拿真实场景的第二意见）、OWASP ASVS 5.0（把自查单升级成完整验收表）、NIST SP 800-63B-4（追踪认证技术演进）。标准会更新，地图不会变：认证、授权、审计，三块地，五环节，桌面版照走。
