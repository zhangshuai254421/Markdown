软件登录与权限系统 · 第 3 课（纯桌面版）

登录窗口与会话进程内会话、失败锁定，以及多机连库时的账号集中

第 2 课解决了「密码列怎么存」，这一课把登录流程的其余部分补齐：校验通过后程序怎么「记住」这个人、登录失败怎么处理。桌面形态的好消息是：没有网络，第 1 课地图上的第①③环节比服务端形态简单一个数量级——但有几个坑照样要绕。

进程内会话：一个静态对象就够

服务端形态需要令牌和会话表，是因为「客户端和服务端隔着网络互不信任」。桌面软件里，登录通过后程序要做的只是在内存里记住当前是谁——软件一关，会话天然消失：

public static class UserSession          // App 级单例——桌面形态的「会话」就这么多
{
    public static LocalUser? Current { get; private set; }
    public static void Login(LocalUser user) => Current = user;
    public static void Logout() => Current = null;
    public static bool IsLoggedIn => Current != null;
}

// 登录窗口校验通过后：
UserSession.Login(user);
new MainWindow().Show();
Close();                                  // 关登录窗

三条纪律：

  1. 会话里只放身份，不放密码——校验完成后原密码就应当丢弃，需要再验证时（如敏感操作前）让用户重输。
  2. 提供显式「切换账号/退出登录」：UserSession.Logout() 回登录窗口。多人共用一台工控机时这是刚需，也是审计能定位到人的前提。
  3. 长时间无操作锁屏（工业现场推荐）：给主窗口挂个计时器，30 分钟无输入弹回登录窗口——对应等保「连接超时自动退出」的桌面版。

登录失败：两件小事

没有网络接口，「在线爆破」的前提不存在了，但登录窗口仍有两件值得做的小事：

  • 话术统一：无论账号不存在还是密码错，都提示「用户名或密码错误」。这能挡住操作员之间「帮同事试密码」式的窥探——成本为零，照做。
  • 简单锁定：连错 5 次锁 5 分钟（内存计数即可，软件重启清零也无妨）。防的不是黑客，是「试密码玩」的同事，和保障「错误密码不会被无限重试」的基本姿态：
private int _failedCount;
private DateTime _lockedUntil = DateTime.MinValue;

private void OnLogin()
{
    if (DateTime.Now < _lockedUntil) { Show("尝试过多，请稍后再试"); return; }

    if (TryVerify(inputUser.Text, inputPwd.Password)) { EnterMain(); return; }

    if (++_failedCount >= 5)
    {
        _lockedUntil = DateTime.Now.AddMinutes(5);   // 桌面简化版：内存计数即可
        _failedCount = 0;
    }
    Show("用户名或密码错误");                          // 统一话术，不区分哪种错
}

多机连库：账号表放进中央数据库

多台电脑装同一软件、直连同一个 SQL Server 的形态：把账号表和审计表放中央数据库，密码校验代码不变（哈希在应用侧算，库里只存哈希）。收益立刻兑现：

  • 禁用一个账号、调整一个角色，全公司即时生效——不用挨台电脑改；
  • 审计记录集中在服务器的数据库里，离开各人的本机，可信度上一个台阶；
  • 顶号：登录时在账号表记一行「活跃终端」，新登录把旧终端顶下线（写一条事件让旧程序自己退出）——解决「同一账号两台电脑同时用」；
  • 数据库账号最小权限：软件连库用的数据库账号只给业务表的读写，不给建表删表权限——它被谁看到都不至于动整库。

选型判断：多台电脑共用数据 → 账号表集中；纯单机软件 → 本地账号表（第 2 课），其余代码完全一样。

课后作业：把登录流程写下来

  1. 画流程：按本课结构写出你家软件的登录流程：校验（第 2 课方案）→ UserSession → 主窗口；失败锁定和无操作锁屏（工业现场建议 30 分钟）要不要。
  2. 定模式：本地账号表（单机）还是中央账号表（多机连库）？理由一句话。
  3. 带回现状：现在的登录失败是什么提示？有没有切换账号功能？——第 5 课做审计时，账号唯一性是前提。
