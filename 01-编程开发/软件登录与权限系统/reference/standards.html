桌面登录权限标准速查做功能查哪份、讲道理引哪份、过测评对哪份

登录权限的「标准」分三层：法律决定为什么必须做，国标决定做到什么程度算合格，国际标准与行业实践给出具体怎么做才对。桌面软件没有服务端，但标准照样适用——只是条款落在你的登录窗口、本地库和命令层上。

一、中国国标与法规（合规层）

标准 / 法规管什么对你的意义
GB/T 22239-2019
网络安全等级保护基本要求（等保 2.0）
官方全文 →		 按系统定级（一至四级）给出安全通用要求；身份鉴别、访问控制、安全审计是安全功能要求项，三级起要求双因素鉴别 登录权限模块的合规底线。桌面软件过测评时，逐条对照「安全计算环境 → 身份鉴别 / 访问控制 / 安全审计」——第 6 课的验收主轴
GB/T 39786-2021
信息系统密码应用基本要求
官方全文 →		 信息系统商用密码（SM 系列算法）应用的技术与管理要求 客户指定国密算法（SM3 摘要/SM4 加密）或要做「密评」时查它——届时密码哈希路线要换成国密方案
《网络安全法》（2017 施行） 确立等级保护制度；第 21 条要求日志留存不少于六个月 审计记录「只增不删、留存 ≥6 个月」的法律依据（自查单 F-23 项）

二、国际标准与行业最佳实践（原理与落地层）

标准 / 实践管什么对你的意义
OWASP Cheat Sheet Series
Password Storage → · Authentication → · Authorization →		 实现要点速查：密码怎么存（算法与参数）、密码策略怎么定（长度/黑名单/不强制换）、授权怎么设计（默认拒绝/最小权限） 写代码前的第一站——第 2、3、4、5 课的参数与原则全部出自这三篇
NIST SP 800-63B-4
Digital Identity Guidelines（2025 定稿）
在线全文 →		 认证的权威技术参考：密码策略（不再建议定期强制换密、要求防撞库黑名单）、盐与慢哈希要求、AAL1–3 保障等级 回答「为什么这么做」时引它——比如推翻「90 天强制换密码」的老规矩
OWASP ASVS 5.0
Application Security Verification Standard
项目页 →		 应用安全验证需求清单，认证、密码、访问控制章节可当验收自查表 客户要求正式验收时，把课程自查单升级成 ASVS 对应条目的桥梁
NIST RBAC（INCITS 359）
项目页 →		 基于角色的访问控制参考模型：核心 / 层级 / 约束（职责分离）三层 第 4 课建模方法的模型出处；「分配权限与查看审计分离」来自约束层
ISO/IEC 27001:2022
附录 A 控制项 5.15–5.18
5.15–5.18 解读 →		 管理体系的访问管理控制簇：访问控制、身份管理、鉴别信息、访问权限 客户或集团要 ISO 27001 认证时的对接语言，视角偏管理流程
用法口诀 存密码查 OWASP，讲策略引 NIST，过测评对等保。三层不冲突：OWASP 告诉你怎么写对，NIST 告诉你为什么这样算对，等保告诉你国内测评时最低要做到哪。（Web 联邦登录协议 OAuth/OIDC/SAML/WebAuthn 属 B/S 生态，桌面课程不展开；将来做 B/S 版本时再回来查。）
