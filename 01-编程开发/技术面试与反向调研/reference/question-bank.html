面试反问速查卡

面试最后 5 分钟用。先挑 2-3 个，不要全问。每个问题都按“问 → 听 → 追问”使用；你要的不是一份标准答案，而是对方愿不愿意、能不能说出具体事实。

只想看清单？打开 R2 · 求职者面试反问备忘录（可勾选、可打印）。

怎么用这张卡

  1. 面试前：从技术 / 工作 / 生存三张地图各挑 1 个，按面试官角色删掉不合适的，只留 2-3 个。
  2. 面试中：先问一句，然后闭嘴听。对方答得越具体，越不用追问；答得越概括，越要追“最近一次”。
  3. 面试后：10 分钟内写原话、打分。别等回家再回忆，记忆会自动美化。

一、万能公式

时间锚点 + 具体事件 + 追问结果。如果只能记住一句：“最近一次……是怎么……的？后来呢？”

封闭题（容易得到空话）证据题（逼出具体事实）你想验证什么
你们有测试吗？最近一次测试没拦住的问题是什么？测试是否真的在拦问题
你们做代码评审吗？上一次评审里，你提过的最重要的意见是什么？评审是走流程还是真讨论
你们加班多吗？上个季度最忙的一周，大家大概几点走？加班是例外还是常态
你们技术债多吗？最近一次专门还技术债是什么时候？做了什么？技术债是否被看见、有偿还机制
你们部署频繁吗？最近一次发布是周几？从合并到上线花了多久？发布流程与压力

证据题不是“更委婉”，而是“更难被空话回答”。礼貌和具体不冲突：把“有没有”换成“上一次……”，语气反而更自然。

二、12 个高信号问题

每格先问左边，听到概括再追中间，最后用右边判断。问题不必全问；一轮挑 2-3 个就够。

技术真相（问工程师 / 技术面）

问法追问听什么
1. 最近一次线上故障是怎么发现的？后来改了什么？ 谁处理的？有复盘吗？同样问题再发生会怎样？ 危险：想不起来 / 说没有线上故障。
好：能说出时间、发现方式（监控 / 用户 / 测试）、处理过程、后续改动。
2. 一个改动从提交到上线，必须过哪些检查？ 上一次是哪一步拦住了问题？哪一步最常失败？ 危险：没有固定流程 / 直接改服务器。
好：能说出评审、自动化测试、构建、发布步骤，并有最近拦截例子。
3. 上一次代码评审里，你提过的最重要的意见是什么？ 评审一般看多久？会拦下合并吗？ 危险：走形式 / 只看格式 / 不怎么评审。
好：具体的设计、边界、风险问题，说明评审真在讨论。
4. 最近一次专门还技术债是什么时候？做了什么？ 如果不还，会先在哪里出问题？ 危险：没有技术债 / 都是祖传代码不敢动。
好：能指出具体模块、依赖和业务约束，说明团队知道债在哪。

工作真相（问直属主管）

问法追问听什么
5. 上一个赶进度的项目，你们妥协了什么？ 后来补了吗？谁做的取舍决定？ 危险：从不妥协 / 都按计划完成。
好：承认取舍（测试、文档、重构），说明补偿或遗留风险。
6. 上个季度最忙的一周，大家大概几点走？ 这种情况一年大概几次？忙完有调休 / 补偿吗？ 危险：经常 / 习惯了 / 说成文化。
好：能给出频率和原因，承认忙季存在，也有恢复安排。
7. 需求是谁排的？工程师对排期有异议时，通常怎么处理？ 能举一个最近被工程师推回去的例子吗？ 危险：老板说了算 / 没有异议。
好：能说出优先级机制、推回案例和结果。
8. 如果我入职，前三个月你希望我解决什么问题？ 怎么判断我做对了？有哪些文档 / 人能帮我上手？ 危险：先熟悉业务 / 没有明确目标。
好：具体目标、可衡量结果、onboarding 安排。

生存真相（问主管 / HR / 终面）

问法追问听什么
9. 这个岗位为什么开放？是新增还是替补？ 如果是替补，方便说说前任离开的原因吗？团队流动大吗？ 危险：含糊 / 正常流动 / 不愿说。
好：能说明业务原因或离职背景，不回避。
10. 团队现在最头疼的问题是什么？ 这个问题存在多久了？谁在负责？正在怎么解决？ 危险：没有问题 / 都是小问题。
好：具体问题、影响、正在做的尝试。
11. 团队里待得最久的人是谁？这位同事为什么留下？ 团队平均待多久？最近一年走了谁？ 危险：都是新人 / 答不上来。
好：具体的人、年限、留下的原因，说明团队有留存。
12. 公司 / 业务未来一年最大的挑战是什么？ 这个岗位和它有什么关系？如果没解决，团队会怎样？ 危险：没有挑战 / 都是机会。
好：真实挑战、应对计划、岗位角色。

公式是默认，不是唯一。少数具体的目标题（如“前三个月你希望我完成什么”）也有效，因为它们要求具体承诺；但“你怎么看 X”这类观点题最容易得到客套话。另有一个进阶问法：“如果只能删掉一个模块，你最想删哪个？为什么没删？”——它用具体假设逼出真实约束，适合在建立信任后问。

三、按面试官角色选

面试官优先问暂时别问
技术面（未来同事）技术真相 1-4；团队日常薪资、假期、公司战略
直属主管工作真相 5-8；生存真相 9-10太细的技术实现
HR / 终面生存真相 9-12；流程、薪酬、试用期技术细节、团队八卦

同一个问题可以问两个面试官。不是不信谁，而是看答案是否对得上；互相矛盾往往比“答得不好”更有信息量。

四、红旗与绿旗

绿旗

  • 能坦然说“这块我们做得不好，正在……”
  • 能说出最近一次故障 / 事故的处理和后续改动
  • 对技术债、排期取舍有具体例子
  • 面试官也认真问你问题，像双向选择
  • 团队里有待了 3 年以上的人，并能说出为什么留下

红旗

  • 所有回答都是形容词，举不出最近的具体例子
  • 不同面试官对同一问题说法矛盾
  • “我们测试很全”却说不清上一次测试拦住了什么
  • 把长期加班说成“奋斗者文化”，没有调休 / 补偿
  • 岗位长期开放、前任频繁更换、离职原因含糊

单个信号不能定罪，看模式、做交叉验证。面试官也可能受保密约束，不能透露细节；要区分“不愿说”和“不能说”。匿名评价（脉脉、看准、Glassdoor）可以当外部线索，但样本偏差很大，别当判决书。

五、面试后 10 分钟评分表

维度1 分3 分5 分你的分
具体性全是形容词有一两个例子时间 / 人物 / 后续齐全
一致性多人说法矛盾大致一致互相补充且不矛盾
坦诚度回避问题只谈优点主动谈问题与取舍
技术基线无测试 / 无评审 / 无 bug 库有流程但说不清能说出流程与最近事件
人的状态长期加班 / 高流动偶尔加班节奏可持续

25 分制。分数是记录工具，不是判决：低于 15 分先看哪一维拉低；高于 20 分也别忽略红旗。最重要的是旁边写下对方的原话。

六、开场白与追问句

开场（先说明意图 + 数量）：

“我想了解一下团队平时怎么工作，方便问两个具体的问题吗？”

“如果方便的话，我想请教一个最近的实际例子……”

追问句库：

  • “能举一个最近的例子吗？”
  • “后来呢？”
  • “当时是谁做的决定？”
  • “如果同样的情况再发生，你们会怎么做？”
  • “这个问题你们现在有改进计划吗？”
  • “还有什么是你觉得我作为候选人应该知道的？”

收尾大问题：“这份工作 / 团队 / 公司最好和最坏的方面是什么？”——来自 reverse-interview 的 catch-all，通常能逼出前面没说的真话。

七、来源

  • Julia Evans, “Questions I'm asking in interviews”——工程实践 / 管理风格 / 生活质量问题清单。
  • Joel Spolsky, “The Joel Test: 12 Steps to Better Code”——12 条工程基线。
  • viraptor/reverse-interview 及其简体中文版——反向面试问题库。
  • Rob Fitzpatrick, “The Mom Test”——问过去具体事件，不问未来观点。
  • SHRM, “Interviewing Basics”——行为面试：过去行为预测未来行为。
