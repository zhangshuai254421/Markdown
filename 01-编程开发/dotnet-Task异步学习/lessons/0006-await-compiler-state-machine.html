前五课你反复听见同一句话:"await 等欠条,完成即恢复。" 但"暂停一个方法再恢复"听起来像魔术——线程没有暂停键,栈帧也不会自己消失再回来。 今天把魔术拆开:await 是编译器的障眼法,它把你的 async 方法整个搬进一个类, 切成段,提前返回。面试高频 源码视角

〇、隔日检索(先测后学:0005 还剩多少?)

一、魔术为什么不可能是真的

先想清楚物理约束:线程只能执行,不能暂停。线程跑完当前方法就顺着调用栈 往下走;所谓"方法暂停在 await 上",意味着一张栈帧凭空冻住——CPU 和执行模型里没有这种东西。

所以唯一可能的解释是:编译器改写了你的代码。"暂停"根本没发生,发生的是:

  1. 你的 async 方法被拆成几段(await 是切缝);
  2. 遇到未完成的欠条,登记一个回调,然后提前 return——线程正常离开;
  3. 欠条完成时,有人替你把下一段重新调起来——这就是全部的"恢复"。

今天的单一收获

看完本课,你要能对着任何 async 方法,在白板上手写还原编译器生成的状态机骨架。 这个能力直接服务三个动机:读框架源码(源码里全是状态机思路)、面试讲 await 原理、 调试时看懂反编译产物。

二、拆开看:源码 → 编译器产物

从一个最小的 async 方法开始:

你写的源码
// 一句一动作:打印、await、打印、返回
public async Task<int> LoadCountAsync(HttpClient http, string url)
{
    Console.WriteLine("开始下载");                       // ① await 之前
    byte[] bytes = await http.GetByteArrayAsync(url);   // ② 切缝在这里
    Console.WriteLine($"拿到 {bytes.Length} 字节");      // ③ await 之后
    return bytes.Length;                                // ④ 返回
}

编译器看到 async,做的事是:新建一个嵌套类,把整个方法体搬进它的 MoveNext() 方法,按 await 切段,再生成一个薄外壳方法。下面是骨架还原 (简化自 Stephen Toub 的逐层拆解,保留了全部关键结构):

编译器产物 · 状态机骨架(手写还原)
[CompilerGenerated]
private sealed class LoadCountStateMachine : IAsyncStateMachine
{
    public int State;                // 段号:-1 = 首次进入;0 = 已过一个 await
    public TaskAwaiter Awaiter;      // 临时:正在等的那个欠条的"读取器"

    // ↓ 跨 await 存活的局部变量,被"提升"为字段(hoisting)
    public HttpClient Http;
    public string Url;

    // ↓ 负责开出并完成那张欠条(Task)的角色
    public AsyncTaskMethodBuilder<int> Builder;

    void IAsyncStateMachine.MoveNext()      // ← 你的方法体全体,住在这里
    {
        switch (State)
        {
            case -1:   /* ── 段 1:await 之前 ── */
                Console.WriteLine("开始下载");
                Awaiter = Http.GetByteArrayAsync(Url).GetAwaiter();
                if (!Awaiter.IsCompleted)              // 欠条还没完成?
                {
                    State = 0;                         // 记住"下次从段 2 继续"
                    Builder.AwaitUnsafeOnCompleted(ref Awaiter, ref this);
                    return;                            // ← 方法到此返回,线程走人!
                }
                goto case 0;                           // 已完成 → 直接走段 2

            case 0:    /* ── 段 2:await 之后 ── */
                State = -1;
                int count = Awaiter.GetResult();       // 取结果;异常也从这里重抛!
                Console.WriteLine($"拿到 {count} 字节");
                Builder.SetResult(count);              // 销账:我们欠的 Task 完成
                return;
        }
    }
}

而你实际调用的,只是一个薄外壳(shell/stub)——创建状态机、点火、交出欠条:

外壳方法 · 你签名里那个"原方法"
// async 关键字在编译后消失;外壳里没有任何你的逻辑
public Task<int> LoadCountAsync(HttpClient http, string url)
{
    var sm = new LoadCountStateMachine();        // 状态机 = 堆上的普通对象
    sm.Http = http; sm.Url = url;
    sm.Builder = AsyncTaskMethodBuilder<int>.Create();
    sm.Builder.Start(ref sm);                    // 点火:立刻执行一次 MoveNext()
    return sm.Builder.Task;                      // 交出欠条——调用者拿到 Task
}

源码↔产物的完整对照表已放进 await 状态机速查卡(新增)。 真实产物比骨架更抠:状态机其实是 struct、能不装箱就不装箱(异步方法零分配的由来)—— 结构相同,细节问老师或读 Toub 原文。

你写的编译器变成
async 方法嵌套状态机类 + 一个薄外壳方法
跨 await 的局部变量状态机的公共字段(提升 hoisting)
await 之前的代码case -1 段
await 那一行IsCompleted 分岔 + 登记续延 + return
await 之后的代码case 0 段
方法的 returnBuilder.SetResult(...)
抛出的异常Builder.SetException(ex)

三、亲手走一遍:MoveNext 的慢路径与快路径

对着上面骨架,依次播放两条路径——注意徽章里欠条状态的每一步变化,它们和 0005 的状态地图严丝合缝:

两条路径对照出的设计

慢路径的全部代价 = 一个状态机对象 + 一次续延登记;快路径零注册零调度。 这就是高性能库敢在热路径上大量 await 的底气:只要数据常常已就绪,await 基本免费。 真实的"暂停感",只存在于慢路径里那一次提前 return。

四、把骨架焊进脑子:六个关键事实

  1. 没有暂停,只有拆段 + 提前返回。await 遇到未完成的欠条 = 登记回调 + return。 调用者立刻拿到欠条,线程正常走人。
  2. 局部变量被提升为字段。栈帧要销毁,跨 await 的变量必须搬到堆上的状态机里—— 这就是"await 之后为什么还能用 bytes"的机械答案。
  3. 恢复 = 完成者调用 MoveNext()。欠条完成 → 续延执行 → 状态机从断点段继续。 默认就在完成者的线程上内联执行(0002 讲过的恢复语义)。
  4. async 方法自己就是出票人。Builder.SetResult 正是 0001 四种出票人的 第一种——你现在能说出它的机械细节了。await 的每张欠条背后,都有一个状态机在销账。
  5. 快速路径让 await 近乎免费。欠条已完成(IsCompleted == true)→ 不登记、不挂起,顺序走完。缓存、已完成数据源都走这条。
  6. 调用堆栈为什么是"断"的。每次真实暂停 = 一次方法返回 + 一次被 MoveNext 重新拉起。 调试器里 async 方法出现在不连续的栈之间,原因在此。

异常的归途补上最后一块(骨架里省略的 try/catch,真实产物必有):

骨架里省略的异常通道
void MoveNext()
{
    try   { /* 你写的所有段 */ }
    catch (Exception ex)
    {
        Builder.SetException(ex);   // 普通异常 → 欠条 Faulted
                                    // OCE      → 欠条 Canceled(0005 的 TAP 规则,就实现在这!)
    }
}
前课概念状态机里的真身
欠条的生产者半张(0001)Builder + MoveNext:async 方法本身就是出票人
续延(0002)AwaitUnsafeOnCompleted 登记的那个"完成后叫我"
默认内联恢复(0002)完成者线程直接跑你的 case 0 段
状态流转(0005)SetResult / SetException 就是流转扳机
广播安全(0004)SetResult 触发欠条上的所有续延,终态不可变兜底
