Task 组合器:WhenAll / WhenAny / Delay / Unwrap

⏱ 预计 25 分钟 前置:第 0003 / 0008 课 交付:一次驾驭一批欠条——并发聚合与竞速

前八课你一直在跟单张欠条打交道。真实系统里,活都是成批的: 并发拉三个数据源、竞速五个镜像、给任何等待配一个节拍器。组合器就是把 一批欠条合成一张欠条的批量操作——合成出来的仍是欠条:可 await、可挂超时、可传人, 前八课的一切机制原样适用。面试高频 源码视角

〇、隔日检索(先测后学:0008 还剩多少?)

一、从一张到一批:先看最常见的假并发

串行 vs 并发 · 一字之差,三倍时差
// × 串行:总耗时 = 100 + 100 + 100 = 300ms
var a = await GetAAsync();   // 等完才发起下一个
var b = await GetBAsync();
var c = await GetCAsync();

// ✓ 并发:先发起,后聚合——总耗时 ≈ max(100,100,100) = 100ms
Task<string> ta = GetAAsync();   // 三张欠条同时放出去
Task<string> tb = GetBAsync();
Task<string> tc = GetCAsync();
string[] r = await Task.WhenAll(ta, tb, tc);   // 合成一张再等

口诀:先发起,后聚合

假并发的根源是把 await 写进了发起的节奏里——每 await 一次就 站着等一张。WhenAll 本身不发起任何任务,它只是等待; 并发发生在一个个欠条被放出去的瞬间。

组合器合成欠条何时完成一句话用途
Task.WhenAll全部结束(含故障)才结算并发聚合全部结果
Task.WhenAny第一张结束(含故障)即结算超时、竞速、任一即可
Task.Delay时间到(可被令牌打断)节拍器、退避、超时伴跑
Unwrap()把嵌套欠条拍平成一层拆 Task<Task<T>>

二、WhenAll:三个事实

面试高频会用的人多,说准的人少:

  1. 结果顺序 = 传入顺序。r[0] 对应第一张欠条——不是谁先完成谁在前。 结果定位不靠完成时序,靠位置约定。
  2. 异常聚合。多张同时故障时,await 处只重抛第一个异常; 全部异常打包在 task.Exception(AggregateException)里。要逐个处理得自己拆包(0010 展开)。
  3. 失败不传染,也不提前结束。某张欠条故障,其余照跑;合成欠条要等 所有欠条终态才结算。想要"一败即停",得自己配 CancellationToken(见当堂实验室场景 2)。

权威语义:Task.WhenAll API — Microsoft Learn; 规范级出处是 TAP 规范(组合器一节)。

三、WhenAny:竞速与超时(0003 的地基,今天兑现)

两个事实,一个陷阱:

  1. "第一张完成"包括故障与取消。合成欠条在任一张到达终态的瞬间结算—— 那张可能是坏消息。完成 ≠ 成功,取值前先验明正身。
  2. 其余欠条不会停。结算只代表"不用等了",不代表"其余取消"—— 不收尾,它们就白跑一路(0008:每一个都是资源)。
竞速模板 · 谁先回用谁,其余即撤
using var cts = new CancellationTokenSource();
Task<string>[] mirrors = urls
    .Select(u => _http.GetStringAsync(u, cts.Token))   // 全部带着令牌出发
    .ToArray();

Task finished = await Task.WhenAny(mirrors);           // 第一张终态即回
cts.Cancel();                                          // 撤回其余(0003:超时≠取消的反向运用)

string winner = await (Task<string>)finished;          // 取胜者结果(或重抛其异常)

连回 0003

超时模式 WhenAny(work, Task.Delay(timeout)) 就是这个模板的特例: Delay 扮演"陪跑者"。0003 讲过它的坑(弃等 ≠ 取消、Delay 欠条泄漏)——今天你看到的是 同一枚硬币的另一面:WhenAny 之后,收尾永远是你的义务。

四、Delay 与 Unwrap:两个小件

Delay:时间驱动的欠条。用 0008 的判决尺一秒判明它与 Thread.Sleep 的区别:Sleep 占一个工人干等;Delay 是真异步,零线程。 用途:轮询节拍、重试退避(每次 Delay 加倍)、给 WhenAny 当超时陪跑;第二个参数传 CancellationToken 可被提前打断。

Unwrap:嵌套欠条拍平器。嵌套从哪来?两个工厂行为不同:

经典事故:StartNew 不解包
// Task.Run:重载"内置" Unwrap → 拿到 Task<string>(0008 埋的伏笔)
Task<string> t1 = Task.Run(async () => await GetAsync());

// Task.Factory.StartNew:历史遗留,不解包 → 拿到 Task<Task<string>>!
Task<Task<string>> t2 = Task.Factory.StartNew(async () => GetAsync());

await t2;              // × 只完成了"外层"——内层欠条还悬着!
await t2.Unwrap();     // ✓ 拍平成 Task<string>,才是真欠条

两个工厂的完整分野:Task.Run vs Task.Factory.StartNew — Stephen Toub。 一句话:现代代码用 Task.Run;见到 StartNew 包 async 委托,先找嵌套。

五、当堂实验室:四种场景的账本

依次播放(时间按比例压缩)。盯住徽章(合成欠条何时结算)和 结算后仍在生长的时间条(其余欠条的命运):

四个场景,四条账

①并发值 max 不值和;②故障不传染但要等全部;③结算不等于其余停止;④完成的可能是坏消息。 这四条就是 WhenAll/WhenAny 的全部行为边界——面试考的从不超出这四条。

七、明天的回忆任务(30 秒,不翻书)

① 假并发的根源与口诀? 把 await 写进发起节奏 = 每次站着等一张。口诀:先发起,后聚合;WhenAll 只是等待,不发起。
② WhenAll 三事实? 结果按传入顺序;异常聚合成 AggregateException(await 只重抛第一个);失败不传染、等全部结束才结算。
③ WhenAny 的"完成 ≠ 成功"与收尾义务? 第一张终态(含故障/取消)即结算;await 胜者可能重抛异常,先判断再取值;其余欠条要主动 Cancel 或收尾。
