异常处理速查卡

来源:第 0010 课 主推阅读:ExceptionDispatchInfo — Microsoft Learn

一句话:await 解包,Wait/Result 打包; 堆栈是案发现场——throw ex 毁现场,throw; 保现场,EDI 存现场。

一、两套规则总表

消费方式抛出形状多异常
await task原始异常(解包)仅第一个
Wait() / ResultAggregateException(打包)全在 InnerExceptions
GetAwaiter().GetResult()原始异常(仍同步阻塞!)仅第一个
task.Exception 属性AggregateException?(不抛,取出看)全部——WhenAll 拆包靠它

二、WhenAll 全异常拆包(三步模板)

Task<int[]> all = Task.WhenAll(jobs);      /* ① 先留住合成欠条本体 */
try { var r = await all; }                /* ② 正常拿结果(await 只给第一个) */
catch (Exception) {
    foreach (var ex in all.Exception!.InnerExceptions) /* ③ 拆全部 */
        Log(ex);
}

接不到 catch (AggregateException) 当 await 已拆包;Flatten() 拍平嵌套;Handle(pred) 批量筛。

三、四种上抛写法对比

写法堆栈判断
throw;保留✓ catch 内原样上抛
throw ex;重置为当前行× 几乎总是错误
EDI.Capture(ex).Throw()保留原始完整✓ 存起来日后再抛(跨方法/线程)
catch (ex) when (条件)不中即自然上飞✓ 精准过滤,零重置零开销

四、五条纪律

①async 代码用 await 接异常,不用 Result/Wait(形状对 + 免死锁)
②WhenAll 全异常:先留本体,再拆 .Exception
③绝不 throw ex;异地重抛用 EDI(欠条重抛内部即 EDI,0006)
④过滤用 catch when;OCE 只表取消(0005),用 catch (OCE) when (ct.IsCancellationRequested) 辨析(0003)
⑤async void 异常无人能接、直闯 SyncContext——仅限事件处理器(0001/0007)

五、术语表增量

解包 unpackingawait 把聚合拆开,重抛第一个真实异常
打包 wrappingWait/Result 用 AggregateException 携带全部
堆栈重置throw ex 把案发现场改写成当前行——毁证
ExceptionDispatchInfo捕获异常对象并保留原始堆栈异地重抛的工具
异常过滤器catch when:谓词不中 = 未捕获,自然上飞

六、面试自测五问

① await 抛的和 Result 抛的,为什么不一样? 历史层次:TPL 时代打包携带多异常;async/await 时代为了"像同步代码"而解包,catch 见到原始形状。
② 三个任务各抛一异常,await WhenAll 收到几个? 1 个(第一个);要全部需先留 WhenAll 本体再取 all.Exception.InnerExceptions。
③ EDI 解决什么问题? 异常是对象,但直接存下来再 throw 会丢原栈;EDI.Capture 冻结原始堆栈,Throw 原样重抛——Task 故障重抛内部即用 EDI。
④ catch (Exception ex) { throw ex; } 错在哪? 重置堆栈,案发现场变成 catch 那一行,排障线索全毁;要上抛用 throw;。
⑤ Handle(Flatten) 何时用? 遍历聚合、按谓词消化已处理项(Handle 后未处理项再聚);嵌套聚合先 Flatten 拍平。
