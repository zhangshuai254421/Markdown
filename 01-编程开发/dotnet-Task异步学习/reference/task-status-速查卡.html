Task 状态速查卡

三区:出生(静止)→ 运行(活着)→ 终态(不可变)

八种状态全表

区TaskStatus含义怎么离开
出生Created手动 new 后、Start 前的静止态Start() → WaitingToRun
运行WaitingForActivation等完成信号;TCS 欠条的默认态完成信号 → 终态
运行WaitingToRun已入线程池队列,未被工人取走工人取走 → Running
运行Running正在某线程上执行执行结束 → 终态
运行WaitingForChildrenToComplete父任务等 attached 子任务子任务完成 → 终态
终态RanToCompletion成功;唯一令 IsCompletedSuccessfully 为 true不可变
终态Faulted异常;await 处重抛不可变
终态Canceled取消;await 处抛 TaskCanceledException不可变

属性映射

属性true 的条件易错点
IsCompleted任一终态≠ 成功;Faulted 也是"完成"
IsCompletedSuccessfully仅 RanToCompletion.NET Core 2.0+;老项目用 Status == RanToCompletion
IsFaultedFaulted异常在 task.Exception(AggregateException)
IsCanceledCanceledasync 方法抛 OCE 也会到这

Canceled vs Faulted 分界

// async 方法抛 OCE → Canceled(TAP 规则;await 抛 TaskCanceledException)
throw new OperationCanceledException();

// async 方法抛普通异常 → Faulted(await 重抛原异常)
throw new Exception("boom");

// TCS 侧:SetCanceled() → Canceled;SetException(OCE) → Faulted

工程纪律:别拿 OCE 当普通业务异常抛;收到 TaskCanceledException 也别断定一定是别人取消。

生产诊断:滞留状态 → 病灶

滞留状态病灶下一步
WaitingForActivation 太久没人销账:完成路径缺失 / 事件先于订阅溜走审查完成路径与订阅顺序(0004)
WaitingToRun 堆积线程池排队爆满(饥饿)查 ThreadPool 计数(0008)
Running 卡死死循环 / 同步阻塞占用工人抓 dump 看线程栈(0007/0008)
 
// 一行诊断日志
_logger.LogInformation("task = {Status}", task.Status);

术语表补充

终态不可变三终态进入即不变;欠条广播安全与 Try\* 竞速语义的根基
OCEOperationCanceledException;async 方法抛出 → 任务进 Canceled
饥饿 starvation线程池工人不足,任务滞留 WaitingToRun 的现象
attached 子任务附加到父任务的子任务;父任务等它完成后才进终态
