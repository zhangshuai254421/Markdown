Task 组合器速查卡

来源:第 0009 课 主推阅读:TAP 规范 · 组合器

一句话:组合器把一批欠条合成一张欠条—— 合成产物仍是欠条:可 await、可挂超时、可传人。口诀:先发起,后聚合。

一、四组合器总表

组合器合成欠条何时结算结果异常典型用途
Task.WhenAll全部终态才结算数组,按传入顺序聚合成 AggregateException;await 重抛第一个并发聚合全部结果
Task.WhenAny第一张终态即结算先完成的那张(嵌套一层)结算不含异常;胜者可能故障超时、竞速、任一即可
Task.Delay时间到(令牌可打断)无结果令牌取消 → Canceled节拍、退避、超时陪跑
Unwrap()随内层欠条拍平一层透传内层拆 Task<Task<T>>

二、WhenAll 三事实 + 串行陷阱

①结果顺序 = 传入顺序(定位靠位置,不靠完成时序)
②异常聚合:await 只重抛第一个;全部在 task.Exception 里待拆(0010)
③失败不传染、不提前结束;要"一败即停"须自己配 CancellationToken
 
// × 串行(总耗时相加)         // ✓ 并发(总耗时 ≈ max)
var a = await GetAAsync();      var ta = GetAAsync();
var b = await GetBAsync();      var tb = GetBAsync();
var c = await GetCAsync();      var tc = GetCAsync();
                                var r  = await Task.WhenAll(ta, tb, tc);

三、WhenAny 竞速模板 + 两个陷阱

using var cts = new CancellationTokenSource();
Task<string>[] mirrors = urls.Select(u => _http.GetStringAsync(u, cts.Token)).ToArray();
Task finished = await Task.WhenAny(mirrors);
cts.Cancel();                                    // 收尾:撤回其余
string winner = await (Task<string>)finished;    // 或重抛胜者异常

陷阱两枚

① 完成 ≠ 成功:第一张终态含故障/取消;await 胜者前先验明正身。
② 结算 ≠ 其余停止:不 Cancel/收尾,其余欠条白跑一路(0008:每个都是资源)。 0003 的 WhenAny(work, Task.Delay(t)) 超时模式即本模板特例。

四、Delay vs Sleep · 嵌套欠条来源

Task.DelayThread.Sleep
线程占用零线程(真异步)占工人干等(0008 判决尺)
可打断传 CancellationToken 可提前取消不可
用途节拍、退避、超时陪跑仅极特殊同步场景
工厂async 委托的返回结论
Task.Run内置解包 → Task<T>✓ 现代默认(0008)
Task.Factory.StartNew不解包 → Task<Task<T>>× 经典事故;修复:.Unwrap()

五、选型决策

要全部结果→ WhenAll(记住三事实)
要最快一个 / 超时兜底→ WhenAny + 令牌收尾
要节拍 / 退避 / 陪跑→ Task.Delay(勿用 Sleep)
见到嵌套欠条→ .Unwrap() 或换 Task.Run
要"一败即停"的并发→ WhenAll + 共享 CTS:任一故障即 Cancel 其余(故障后检查其余状态)

六、术语表增量

组合器 combinator把一批欠条合成一张的批量操作;产物仍是欠条
AggregateException异常容器:WhenAll 的打包格式;InnerExceptions 可枚举(0010 展开)
竞速 racing多路并发取最先;必须配收尾(取消其余)
退避 backoff重试间隔递增(常 ×2 + Delay);配组合器可做指数退避
嵌套欠条Task<Task<T>>:外层完成 ≠ 内层完成;StartNew 的历史遗留

七、面试自测五问

① 先 await 再发起下一个,错在哪? 那是串行:总耗时相加。并发 = 先把欠条全部放出去,再 WhenAll 聚合;WhenAll 本身不发起任务。
② WhenAll 五个任务各抛一个异常,await 抛几个? 重抛第一个;其余四个在合成欠条的 AggregateException.InnerExceptions 里。要全部处理需拆包。
③ WhenAny 之后其余欠条的状态? 仍在运行。结算只是"不再等待";不收尾就浪费资源——竞速模板里 cts.Cancel() 是标准动作。
④ Task.Delay(Timeout.Infinite, ct) 常用来干嘛? 构造"永不自己完成、只听令牌"的哨兵欠条——与 WhenAny 配合做纯取消等待。
⑤ StartNew 包 async 委托的事故机理? StartNew 返回外层 Task<Task<T>>;await 只完成外层(内层还悬着)。Run 重载内置 Unwrap,故现代代码用 Run。

混合取消+故障时 WhenAll 终态的边角规则值得动手验证——或直接问老师。
