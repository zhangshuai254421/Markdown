TaskCompletionSource 速查卡

一句话:TCS = 你亲手控制一张 Task 欠条何时、以何种结果销账

心智模型:欠条的两半

生产者 持 TCS,调 Set* 销账
Set*()
tcs.Task 同一张欠条,人人可 await
await
消费者 完成后续延恢复

Task ≠ 线程。完成之前欠条里什么都没有;等待不占用任何线程。

五件套 API

成员作用关键细节
.Task取出欠条每次读取同一实例;可交给任意多个 awaiter
SetResult(v)成功销账仅一次;重复抛 InvalidOperationException
SetException(ex)记坏账await 处重新抛出;Wait()/.Result 则包成 AggregateException
SetCanceled()注销await 处抛 TaskCanceledException
TrySetResult / TrySetException / TrySetCanceled安全版返回 bool;竞态场景(超时兜底已抢先)必用

构造选项

// 默认:续延"内联"在调用 Set* 的线程上继续执行
new TaskCompletionSource<T>()

// 让续延改走线程池排队,不在完成者线程上跑(防重入/锁内完成时用它)
new TaskCompletionSource<T>(TaskCreationOptions.RunContinuationsAsynchronously)

// .NET 6+:传入令牌,令牌取消时 Task 自动进入 Canceled(超时模式的官方捷径)
new TaskCompletionSource<T>(cancellationToken)

// .NET 5+:非泛型版,产无值欠条 Task
var tcs = new TaskCompletionSource();

黄金模板:回调 → Task

public Task<double> ReadAsync()
{
    var tcs = new TaskCompletionSource<double>();

    legacy.Read(
        onSuccess: v  => tcs.SetResult(v),
        onError:   ex => tcs.SetException(ex));

    return tcs.Task;
}
// 调用端:var v = await bridge.ReadAsync();

何时用 / 何时不用

✅ 包装回调式 / 事件式老 API❌ 方法体本身能用 async/await 写(那是更简洁的出票方式)
✅ 超时、竞态下"先到先完成"的控制❌ 只是想要后台执行(那是 Task.Run 的事)
✅ 异步初始化、一次性广播完成信号❌ 需要多次发值的生产-消费(那该看 System.Threading.Channels)

四大坑

坑症状解法
① 二次完成InvalidOperationException无竞态:用 Set* 让 bug 显形(断言);有竞态(超时/取消兜底):用 TrySet* 容错,后到者得 false 静默放弃
② 忘记完成await 永久悬挂;闭包引用无法释放(内存泄漏)超时兜底:WaitAsync 或 TCS+Timer
③ 竞态抢销账两个路径都想 Set,后到的抛异常TrySet* 按返回值分支
④ 续延内联在完成者线程持锁调 Set* → 续延在锁内跑 → 重入/死锁构造时加 RunContinuationsAsynchronously

术语表(本课程统一用语)

欠条 / Task未来结果的凭据;官方称"promise / future"式占位符
出票 / 生产者 Producer创建并负责完成 Task 的一方
持票 / 消费者 Consumerawait Task 的一方
销账 / 完成Set* 使 Task 进入终态,只能发生一次
续延 continuationawait 之后的代码;Task 完成时被调度执行的那段
WaitingForActivation欠条已开出、还没销账的状态(TCS 场景最常见)
RanToCompletion / Faulted / Canceled三种终态:成功 / 异常 / 取消
sync-over-async用 .Result/.Wait() 阻塞等待异步代码——死锁之源
