超时控制模式速查卡

一句话:超时管"不再等",取消管"真叫停";两者都要时,令牌 + WaitAsync 组合

核心认知:超时 ≠ 取消

超时(弃等)消费者不再等待,await 抛 TimeoutException 离开;底层操作照跑,迟到结果被竞速语义丢弃
取消(叫停)CancellationToken 显式传入底层,令牌触发时操作真正中止、资源真正释放
组合拳CTS(TimeSpan) 定时触发令牌 + 令牌贯穿底层 + catch-when 转译异常

三式方案对比

方案样板量泄漏风险超时抛出中止底层?
WhenAny + Task.Delay每处 5 行成功路径上延迟任务滞留到计时器触发自己 throw❌
手写 WithTimeout(TCS+CTS)封装一次低TimeoutException❌
WaitAsync(.NET 6+,日常首选)一行无TimeoutException❌
令牌贯穿(CTS + token 传底)每处 3 行无(using 清理)OCE / TaskCanceled✅ 唯一真中止

模板一:弃等(消费者自救)

double temp = await bridge.ReadTemperatureAsync()
                             .WaitAsync(TimeSpan.FromSeconds(5));

// 可再叠加外部取消令牌:
await work.WaitAsync(TimeSpan.FromSeconds(5), cancellationToken);

模板二:真取消(令牌贯穿底层)

using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));

try
{
    var resp = await httpClient.GetAsync(url, cts.Token);  // 令牌进底层
}
catch (OperationCanceledException) when (cts.IsCancellationRequested)
{
    // 惯用法:只把"这次超时"转译,其他来源的取消照常上抛
    throw new TimeoutException("请求超过 5 秒,已中止");
}

模板三:手写 WithTimeout(.NET 6 之前 / 理解原理用)

public static async Task<T> WithTimeout<T>(Task<T> task, TimeSpan timeout)
{
    var tcs = new TaskCompletionSource<bool>(
        TaskCreationOptions.RunContinuationsAsynchronously);
    using var cts = new CancellationTokenSource(timeout);
    using var reg = cts.Token.Register(() => tcs.TrySetResult(true));
    if (task != await Task.WhenAny(task, tcs.Task))
        throw new TimeoutException();
    return await task;
}

异常辨析

触发await 抛出要点
WaitAsync(TimeSpan) 超时TimeoutException语义清晰,"就是超时"
令牌触发(CTS 到点 / Cancel())TaskCanceledException ⊂ OperationCanceledException超时取消与其他取消混流,需 catch-when 辨别
欠条二次销账InvalidOperationException竞态路径一律 TrySet*(见 TCS 速查卡)

选型决策

只是调用方不想等(读缓存、防卡 UI)WaitAsync 弃等即可
底层持有昂贵资源(连接/句柄/事务)必须令牌贯穿,真中止
底层无取消接口(老硬件 SDK)弃等 + 竞速丢弃迟到结果(需幂等);文档里写明
高频调用(每秒成百上千次)复用 CTS(TryReset,.NET 6+)或手写 TCS+Timer,减少分配
