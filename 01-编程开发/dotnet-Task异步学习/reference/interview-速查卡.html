一、三大题 60 秒脚本

① 异步死锁为什么发生?

结论同步等待 + 上下文回投 → 四节点循环等待
机理UI 线程 .Result 阻塞自等 → 欠条等续延 → 续延 Post 回 UI 队列 → 不泵消息
纪律库一律 ConfigureAwait(false);应用一路 async;遗留边界隔离
防身ConfigureAwait 只管单个 await 的续延,不传染(三事实)

② sync-over-async 错在哪?

结论同步代码等异步(.Result/.Wait/GetResult),三重代价
机理死锁风险 + 钉死一个工人白烧 + 占用快于补充(约半秒一补)的饥饿放大
纪律能改签名就一路 async;不能改就隔离封装并明知代价

③ Task vs Thread vs ValueTask?

ThreadTaskValueTask
本质OS 工人本身可 await 的欠条struct 欠条(省分配)
成本创建贵(MB 栈)堆分配一次同步命中零分配
适用专属常驻工人默认选择热路径,只消费一次
