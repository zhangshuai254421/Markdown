测试替身速查stub 与 mock 的分工、两种断言路线、NSubstitute 语法与克制清单

替身（test double）= 插进接缝里的假依赖。术语按 Osherove《The Art of Unit Testing》：

名词干什么你的对应物
Dummy只为编译通过占位，从不被真正使用——
Stub替被测对象「接收输入」：返回设定好的数据/异常FlakyChannel 的扔异常部分
Fake有真实逻辑的轻量实现（内存数据库、内存通道）——
Spy替身里「偷偷记录」调用，供测试事后检查RecordingChannel
Mock预先设定「期望被怎样调用」，验证交互NSubstitute 的 Received()
实用二分 stub 管进，mock 管出。stub 替你把依赖的输入安排好（返回值、抛异常），让代码能跑起来；mock 替你盯住依赖的输出端（被调了几次、传了什么、有没有被调）。别被五个名词吓住——干活的就这两类。

两种断言路线

状态断言（state-based）交互断言（interaction-based）
问的问题「产出/落点的东西对吗」「协作方式对吗」
典型断言Assert.Equal(expected, channel.LastWritten)channel.Received(2).Write(...)
适合绝大多数行为——默认选它没有状态可查时：重试次数、该调没调、不该调却调了
风险几乎无过度使用 → 测试变成实现细节的镜子，一重构就碎（Fowler）

NSubstitute 速查

dotnet add package NSubstitute
using NSubstitute;
using NSubstitute.ExceptionExtensions;

var channel = Substitute.For<IFrameChannel>();      // 造替身

channel.IsOpen.Returns(false);                       // stub：安排返回值
channel.When(c => c.Write(Arg.Any<byte[]>()))        // stub：安排抛异常
       .Do(_ => throw new ChannelBusyException());
channel.Write(Arg.Do<byte[]>(b => seen.Add(b)));     // stub：顺手记录（spy 行为）

channel.Received(2).Write(Arg.Any<byte[]>());        // mock：恰好被调 2 次
channel.DidNotReceive().Write(Arg.Any<byte[]>());    // mock：从未被调
channel.DidNotReceiveWithAnyArgs().Write(default);   // mock：不管参数，没调过就行

克制清单（mock 纪律）

  • 默认状态断言，交互断言只留给「没有状态可查」的行为
  • 只 mock 出了边界的依赖（串口、邮件、数据库、时钟）；自己写的纯逻辑不 mock
  • 接口要窄：替身接口的方法越少，替身越便宜，测试越稳
  • 重构实现（行为不变）时，不允许出现莫名红灯——红了说明有测试在照镜子的路，而不是在查行为
