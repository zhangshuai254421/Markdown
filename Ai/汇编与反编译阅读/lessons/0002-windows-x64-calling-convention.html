从 call 读出函数签名：Windows x64 调用约定

第 1 课让你找到输入与控制流；现在要把输入变成“第几个参数、什么类型、结果在哪”。这是读 Windows C++ 反编译最有杠杆的一条规则。

本课的一个胜利：看见 call 前几行时，能先标出参数槽位；看见 call 后使用 rax 时，能标出返回值。不要先猜函数名字。

1. Windows x64 的四个参数槽位

针对本课程的目标平台（64 位 Windows、通常的 MSVC C++），参数按位置编号。前四个位置用寄存器；整数/指针使用通用寄存器，浮点数使用对应的 XMM 寄存器。

参数位置整数或指针float / double
第 1 个RCXXMM0
第 2 个RDXXMM1
第 3 个R8XMM2
第 4 个R9XMM3
第 5 个起栈（调用者在 call 前写入）

最容易漏掉的细节：槽位按参数位置走，而不是“整数一个队列、浮点一个队列”。例如 f(int a, double b, int c, float d) 的位置是 RCX、XMM1、R8、XMM3；RDX 和 XMM2 在这个调用中不用。

2. 读一个调用点

; 假设调用：int Update(Device* device, int mode, int power)
mov  rcx, rbx        ; 第 1 槽：device
mov  edx, 2          ; 第 2 槽：mode
mov  r8d, esi        ; 第 3 槽：power
call Update
test eax, eax        ; 使用 int 返回值
jne  failed

这里能证实的是：调用点向被调函数传了三项，第一项来自 rbx，第二项为常量 2，第三项来自 esi；调用后立刻检查 eax。我们可以假设它是返回状态码，但还不能证实函数名、对象类型或枚举名字。

.NET 类比：这像你在 IL 中看到 call 前的 ldarg/ldloc。区别是 native code 没保留参数名，ABI 规定的是“值在哪”，而不是“值叫什么”。

3. 返回值：先看 RAX，再看 XMM0

  • 能装入 64 位的整数、指针和许多小型简单结构，通常经 RAX 返回；32 位整数表现为 EAX。
  • float、double 和向量类结果，经 XMM0 返回。
  • 大的或复杂的 C++ 对象常由调用方提供“返回缓冲区”地址；它占第 1 槽，使源码参数整体右移。这是以后读 C++ 值返回时的重要例外。
; int IsReady(Controller* c)
mov rcx, rdi
call IsReady
test eax, eax         ; eax 是标量返回值
je   not_ready

4. Shadow space：别误判成四个局部变量

调用方即使只传一个参数，也必须为前四个寄存器参数预留 32 字节栈空间（shadow store / home space）。被调函数在需要时可以把 RCX、RDX、R8、R9 暂存进去。

; 一个典型调用点（示意）
sub rsp, 40h          ; 32 字节 shadow space + 对齐/可能的额外空间
mov rcx, rdi
call SomeFunction
add rsp, 40h

阅读规则：看到围绕 call 的 sub rsp, 20h 或更大分配时，先问“它是否包含 shadow space 和对齐？”；不要立即把每个 [rsp+offset] 都命名为业务局部变量。

5. 哪些寄存器跨 call 仍可信？

类别用于本课的阅读规则
易失：RAX RCX RDX R8 R9 R10 R11经过 call 后，默认当作已毁坏；RAX 往往正承载返回值。
非易失：RBX RBP RDI RSI R12–R15被调函数若使用，按 ABI 必须恢复；常见于跨调用持续存活的值。

这不是说非易失寄存器“永远不变”，而是说被调函数必须让调用者最终仍能看到原值。这解释了函数入口/出口常见的 push rbx … pop rbx。

6. 练习：从调用点回写伪代码

以下 call 的前三个整数/指针参数分别来自哪里？

mov rcx, rsi
mov edx, 1
mov r8d, ebx
call qword ptr [rax+18h]

答案：第 1 个来自 rsi，第 2 个是常量 1，第 3 个来自 ebx。最后一行是经内存中的函数指针间接调用；这可能是虚函数，但仅凭这一处还不能下结论。

为 f(int a, double b, int c, float d) 选对寄存器序列。

答案：RCX, XMM1, R8, XMM3。按位置决定槽位；空着的 RDX / XMM2 不表示漏传参数。

一个 call 返回后，为什么不能继续把 r8 当作调用前那个局部值？

答案：R8 是易失寄存器；ABI 允许被调函数覆盖它。若原值需跨调用保留，编译器会放到栈或非易失寄存器中。

7. 一次刻意练习

  1. 在 Compiler Explorer 选择 MSVC x64。
  2. 输入 int Mix(void* p, int a, int b, int c, int d) { return a + b + c + d + (p != 0); }。
  3. 在 /Od 下，标出 5 个参数的来源；确认第 5 个为何不在寄存器中。再切到 /O2，重复这件事。

主来源：Microsoft: x64 calling convention。本课不要求背完所有 ABI 例外；你只要能在真实调用点稳定地标出四个槽位、栈参数和返回值。哪里别扭就直接问我。
