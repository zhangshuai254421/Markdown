把汇编当成赋值语句读：最小语法

这一课故意不讲函数、栈、调用约定。你的唯一目标是：每一行都能翻译成一条简单的 C# 风格赋值或算术语句。

今天只记一句：指令 目标, 来源 大多可以先读作 目标 = 来源。x86 常用 Intel 语法，目标在左，来源在右。

1. 数字与注释

写法含义.NET 类比
42十进制 4242
2Ah 或 0x2a十六进制 420x2A
; 后面的文字注释，不执行// 注释

反汇编器常把十六进制写成 20h，Ghidra 常见 0x20。它们是同一个数：32。

2. 寄存器：只是不同宽度的“格子”

先只关心两组名字：

64 位低 32 位先这样理解
RAXEAX同一个物理寄存器的不同观察窗口
RCXECX同上
RDXEDX同上
R8R8D同上
一个高频规则：写入 32 位寄存器会把对应 64 位寄存器的高 32 位清零。mov eax, 5 之后可以先当作 rax = 5。但读取 eax 时，只是在读 rax 的低 32 位。

3. 三条指令 = 三种熟悉操作

mov eax, 5       ; eax = 5
mov ecx, eax     ; ecx = eax
add eax, ecx     ; eax = eax + ecx
sub eax, 1       ; eax = eax - 1
imul eax, 4      ; eax = eax * 4

mov 不等于 C# 的对象移动；它只是复制位。add/sub/imul 的第一个操作数同时是输入和输出，就像 x += y。

; 逐行翻译
mov eax, 7       ; eax = 7
mov ecx, 3       ; ecx = 3
imul eax, ecx    ; eax = eax * ecx
sub eax, 1       ; eax = eax - 1
; 结果：eax = 20

4. 方括号 []：不是数组，是“按地址取内存”

这是最重要的一点。没有方括号时，写的是寄存器值；有方括号时，写的是那个值当作地址所指向的内存。

汇编最可靠的翻译
mov eax, ecxeax = ecx
mov eax, [rcx]eax = *(int*)rcx（读 rcx 指向内存）
mov [rcx], eax*(int*)rcx = eax（写 rcx 指向内存）
mov eax, [rcx+8]eax = *(int*)((byte*)rcx + 8)

在反编译中，[rcx+8] 经常最终会被标成 obj->field，但今天先坚持最可靠的说法：读取地址 rcx + 8 的内存。

5. 连起来读

mov eax, dword ptr [rcx+4]
add eax, edx
mov dword ptr [rcx+4], eax

逐行翻译：

int temp = *(int*)((byte*)rcx + 4);
temp = temp + edx;
*(int*)((byte*)rcx + 4) = temp;

你现在不需要知道 rcx 是不是对象、+4 是不是字段。能稳定读出“读 → 算 → 写回”，就是本课完成。

6. 三个自测

mov edx, 12 最接近哪条 C# 语句？

答案：edx = 12;。它不是“把 12 移动到 edx”，而是把 12 的位复制进 edx。

mov eax, [rcx] 与 mov eax, rcx 最大差别是什么？

答案：前者读取 rcx 作为地址所指向的内存；后者复制 rcx 这个地址数值本身。方括号就是“解引用”。

执行后 eax 是多少？

mov eax, 2
mov ecx, 6
add eax, ecx
imul eax, 3

答案：24：先 2，再加 6 得 8，再乘 3 得 24。每次只跟踪被写入的左侧目标。
