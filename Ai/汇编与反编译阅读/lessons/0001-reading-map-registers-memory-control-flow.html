读汇编的地图：寄存器、内存、控制流

你的任务不是背指令，而是把每个函数先还原成 .NET 工程师熟悉的东西：输入、临时值、对象字段和流程图。

本课的一个胜利：看到一段汇编时，先能回答：谁是输入？哪儿读/写内存？代码会往哪几个方向走？能回答这三个问题，就已经在“读程序”而非“背助记符”。

1. 先建立正确的比喻

C# / C++ 视角机器视角
局部变量、参数、返回值某时刻存放在寄存器或栈内存中的位
对象字段基地址加偏移，例如 [rcx+8]
if / while比较/测试后，根据标志位跳转到另一基本块
方法调用按 ABI 准备输入，call；返回后继续，读取结果

寄存器不是“变量的永久住址”。同一个 rax 可以在相邻三行依次装载字段、保存计算结果、承载返回值。阅读时给它取临时语义名，例如 count、isEmpty，一旦被覆盖就丢弃旧含义。

2. 三种最先要认出的形状

; C++: return item->count + 1;
mov eax, dword ptr [rcx+8]  ; 从 rcx 指向对象的偏移 8 读 32 位
add eax, 1                  ; eax = eax + 1
ret                         ; 返回；整数结果在 eax/rax

rcx 在这里像 item，[rcx+8] 像 item->count，eax 最后像返回值。注意：这是根据使用方式形成的假设；反编译工作靠更多调用点和类型信息去验证它。

; C++: return x > 0 ? 10 : 20;
test ecx, ecx               ; 设置标志位：ecx 是否为 0
jle  short else_block       ; 若 x <= 0，跳去 else
mov eax, 10
ret
else_block:
mov eax, 20
ret

不要把 test 和 jle 分开背：把这一对合起来读成「判断 x，选择下一块」。汇编的控制流图才是结构，单条指令只是细节。

反编译的第一纪律：反汇编是“字节解码成指令”；反编译是工具对源码结构的推断。前者更接近事实，后者更易读但可能把类型、变量边界、if 结构猜错。两者不一致时，以数据流和控制流为准。

3. 一个四步阅读法

  1. 划边界：函数入口、所有 ret、所有 call、所有条件/无条件跳转。
  2. 画块：每个分支目标是块入口；先读“块如何连接”。
  3. 标数据：给每个寄存器的当前用途写临时名字；圈出所有 [base+offset]。
  4. 回写源码：只写你能证实的 C++ 伪代码；未知类型先用 uint32_t、void*，别急着编故事。

4. 立即练习

下面最可靠的 C++ 伪代码是什么？

mov eax, dword ptr [rcx+4]
add eax, edx
ret

答案：return *(int*)((char*)rcx + 4) + edx;。可以“猜”它更像 obj->field + value，但当前证据尚不足以确定对象类型和字段名。这里训练的是证据等级。

看到 cmp eax, 5 接 jl target，你应该先把它当成什么？

答案：一个控制流决策：若有符号整数 eax < 5 就去 target。它可能属于 if 或循环；必须看块图，不能只凭一条跳转定结构。

[rcx+8] 最准确的描述是什么？

答案：读取/写入地址 rcx + 8 指向的内存。它可能是对象字段、数组元素或栈外部数据；“字段”是常见但待验证的解释。

5. 用 Compiler Explorer 验证

  1. 打开 Compiler Explorer，选择 MSVC x64。
  2. 输入：struct Item { int tag; int count; }; int Next(Item* item, int delta) { return item->count + delta; }。
  3. 先看 /Od，再切到 /O2；用本课四步法标出输入、内存读和返回值。
