给引擎一张脸WPF 出口层：列表、优先级呈现、搁置清单——与 Prism 合流

引擎现在是全系统唯一懂报警的地方，但它是哑巴——这一课给它一张脸：报警列表、闪烁、声音入口、搁置清单页。出口层的纪律第 7 课就立下了，只有一条：不做任何判定。所以这课写的「逻辑」很少，要守的「纪律」很多——每条呈现规则都必须来自引擎的产出或档案的字段，UI 不许再发明任何一条。

先立接缝：UI 不认得引擎的具体类

public interface IAlarmFeed : IDisposable     // 出口层的接缝
{
    event Action<AlarmEvent> EventRaised;     // 订阅事件流
    IReadOnlyList<ActiveAlarm> Active { get; }  // 查询活跃列表
    void Acknowledge(string tag, string op);
    void Shelve(string tag, TimeSpan duration, string op);
    void Unshelve(string tag);
}

老理由（TDD 课）：ViewModel 对着接口写测试，fake 一个 feed 就能红绿灯，不用起真引擎。引擎在通讯线程吐事件，UI 在 UI 线程消费——这个跨线程编队是本课唯一的技术暗礁，两条路：直接 SynchronizationContext.Post（实验室用，简单直接），或 Prism 的 IEventAggregator（真实项目里解耦更舒服，你有 Prism 底子，选型你来）。

AlarmListViewModel：事件流的 UI 投影

public class AlarmListViewModel : BindableBase
{
    public ObservableCollection<AlarmItemViewModel> Alarms { get; } = new();

    public AlarmListViewModel(IAlarmFeed feed)
    {
        feed.EventRaised += e => _ui.Post(() => Apply(e));   // 跨线程编队到 UI 线程
    }

    private void Apply(AlarmEvent e)
    {
        switch (e)
        {
            case AlarmRaised r:        Alarms.Add(new AlarmItemViewModel(r)); break;
            case AlarmAcknowledged:    Find(e.Tag)?.UpdateState(AlarmState.Acknowledged); break;
            case AlarmAutoReturned:    Find(e.Tag)?.UpdateState(AlarmState.ReturnToNormal); break;
            case AlarmClosed:          Remove(e.Tag); break;
        }
    }
}

看清楚：Apply 里没有一行「判断温度」「判断等级」——UI 只是把事件翻译成集合变更。ActiveAlarm 里 RTN 还在列表、Closed 移出，这些规矩都是引擎定的（第 8 课测试钉死的），UI 照单全收。ViewModel 可测：fake feed 发一个 AlarmRaised，断言 Alarms 集合出现一行——老节奏，先红。

呈现纪律：闪的是「状态」，不是「数值」

<!-- 状态 → 视觉：一条 DataTrigger 一条规矩，全部来自 ISA-18.1 惯例 -->
<Style x:Key="AlarmRow" TargetType="Border">
  <Style.Triggers>
    <DataTrigger Binding="{Binding State}" Value="Unacknowledged">   <!-- 闪红 -->
      <Setter Property="Background" Value="#B3261E"/>
      <Setter Property="Tag" Value="flash-red"/>
    </DataTrigger>
    <DataTrigger Binding="{Binding State}" Value="Acknowledged">     <!-- 稳红 -->
      <Setter Property="Background" Value="#B3261E"/>
    </DataTrigger>
    <DataTrigger Binding="{Binding State}" Value="ReturnToNormal">   <!-- 闪绿 -->
      <Setter Property="Background" Value="#2E7D32"/>
      <Setter Property="Tag" Value="flash-green"/>
    </DataTrigger>
  </Style.Triggers>
</Style>

Tag 上的动画名挂 Storyboard（两帧透明度动画做闪烁）。注意绑定的是什么：State——引擎流转的状态，不是「当前值和限值的差」。UI 一旦开始比较数值，判定权就漏出去了（第 7 课分层就破了）。排序与置顶同理：按档案里的 Priority 排，高优先级永远在顶——操作员第一眼看到的必须是引擎认为最急的。

第三问终于上屏：报警详情 = MADB 的操作指导书

双击报警行弹出的详情页，就是你第 4 课填的那张档案——原因、后果、操作动作、MTR、优先级依据、评审留痕，原样呈现：

<StackPanel>
  <TextBlock Text="{Binding Description}"    FontSize="18" FontWeight="Bold"/>
  <TextBlock Text="{Binding Cause}"          />  <!-- 最可能原因：排查起点 -->
  <TextBlock Text="{Binding Consequence}"    />  <!-- 不处理后果 -->
  <TextBlock Text="{Binding OperatorAction}" FontSize="16" FontWeight="Bold"/> <!-- 该干什么 -->
  <TextBlock Text="{Binding MaxResponseTime, StringFormat=响应窗：{0}分}" />
</StackPanel>

第 1 课的第三问「操作员知道该干什么吗」、第 4 课的「操作动作」字段，在这一屏兑现：报警响 → 操作员点开 → 第一步做什么就写在最显眼的位置。「报警与操作脱节」这个痛，到此在代码里治完。

搁置清单页：正门要有门牌

单独一页，数据就是 feed.Active 按 ShelvedUntil > now 过滤（第 8 课打好的标），每行带「解除搁置」按钮调 feed.Unshelve(tag)。第 3 课说的「搁置清单单独可见」，在这一页兑现——正门要有门牌，被搁置的报警永远找得到。

课后作业：让引擎开口说话

  1. 建 UI 工程：AlarmLab 里加 WPF 项目（Prism 模块化你熟，实验室里单工程也行）。
  2. ViewModel 先红：AlarmListViewModel 对着 fake feed 写第一条测试（feed 发 Raised → Alarms 出现一行），红 → 绿。跨线程编队在测试里用同步执行路径绕过（构造函数注入个同步的「ui」即可——又一个接缝）。
  3. 三态样式：闪红 / 稳红 / 闪绿的 DataTrigger + Storyboard；列表按 Priority 置顶排序。
  4. 详情弹窗：绑定 MADB 字段，操作动作放最显眼处。
  5. 搁置清单页：按标过滤 + 解除搁置按钮。
  6. 带回：跑起来的截图（fake feed 喂三条不同状态的报警最有说服力），或 ViewModel 的绿灯清单。
