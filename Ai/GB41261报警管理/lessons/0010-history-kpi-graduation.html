历史库、体检服务与总答辩最后两块零件装上去，然后——把整个模块讲给我听

九课下来，引擎会思考了（第 8 课），也有脸了（第 9 课）。还差最后两块零件：事件历史库（记本子）和 KpiService（体检中心）。装上它们，你的模块就从「一组代码」变成「一个站进生命周期环的系统」——然后我们答辩。

事件历史库：append-only，引擎不撒谎

第 1 课的「日志是本子」、第 7 课的「全量落库」，落地成一个接口：

public interface IEventStore
{
    void Append(AlarmEvent e);                                    // 只进不改
    IReadOnlyList<AlarmEvent> Query(DateTimeOffset from, DateTimeOffset to, string? tag = null);
}

public sealed class EventHistory
{
    public EventHistory(IEventStore store, IAlarmFeed feed)
        => feed.EventRaised += store.Append;                      // 订阅即落库，一行接线

    // 报警历史 = 事件历史按位号/类型筛出的视图（第 1 课的老话，代码形态）
}

三个要点：只进不改（append-only——改历史 = 毁证据，第 6 课的体检全靠它真）；订阅即落库（引擎产出的每一拍自动进本子，包括带搁置标的——第 8 课「引擎不撒谎」的终点）；存储选型：实验室用 JSONL 文件即可，真项目上 SQLite 单机就够，保留期写进《报警哲学》（常见 90 天～1 年，按你们追溯要求定）。

KpiService：第 6 课的 LINQ 落地成组件

public sealed class KpiService
{
    public KpiService(IEventStore store, IAlarmClock clock);      // 时钟接缝又来了

    public double  AverageRatePerHour(DateTimeOffset from, DateTimeOffset to);
    public int     PeakBucket(DateTimeOffset from, DateTimeOffset to);        // 10 分钟桶
    public double  FloodTimePct(DateTimeOffset from, DateTimeOffset to);      // >10 条/10 分 占比
    public PriorityMix   Distribution();                                      // 高/中/低配比
    public IReadOnlyList<string> ChatteringTags(TimeSpan window, int threshold); // 默认 60s/3 次
    public int StandingCount(TimeSpan now);                                      // >1 时
    public int StaleCount(TimeSpan now);                                         // >24 时
}

课堂示范一条测试（最有趣的那条——颤抖检测）：

[Fact]
public void 同一来源60秒内3次转换_上颤抖榜()
{
    var store = new FakeStore();
    var tag = "HEAT01_TEMP_HI";
    store.Append(new AlarmRaised(tag, At(0, 0, 0), Priority.Medium));
    store.Append(new AlarmClosed(tag, At(0, 0, 20)));     // 20 秒恢复
    store.Append(new AlarmRaised(tag, At(0, 0, 30), Priority.Medium));
    store.Append(new AlarmClosed(tag, At(0, 0, 45)));
    store.Append(new AlarmRaised(tag, At(0, 0, 50), Priority.Medium));  // 60 秒窗口内第 3 次

    var kpi = new KpiService(store, new FakeClock(At(0, 0, 59)));
    Assert.Contains(tag, kpi.ChatteringTags(TimeSpan.FromSeconds(60), 3));
}

固定序列 + 拨表——不用真跑 60 秒，不用连真设备。其余六项指标照第 6 课的算法清单逐条先红后绿。

总答辩：把整个模块讲给我听

零件齐了。结业的标志不是「课听完了」，而是你能把这个模块作为自己的设计讲出来。三道答辩题，答案直接回在对话里：

  1. 架构题：三句话，给你的新同事讲清这个模块为什么分三层、判定权为什么只在引擎。
  2. 开局题：新项目启动，报警部分第一周你做什么？说顺序和理由。
  3. 复发题：半年后报表又开始刷屏，你的排查动作按什么顺序走？
参考轨迹（先自己答，再看） 开局题的期望脉络：写《报警哲学》立判据 → 建事件历史库拿基线（第 7 课迁移第①步）→ 首批档案过评审 → 引擎影子模式。复发题的期望脉络：记分卡定位（哪项红）→ Top-10 找源头 → 颤抖/驻留鉴别诊断（压线恢复还是真复发）→ 该修设计的修设计、该修根因的修根因 → 结果回灌哲学。轨迹对不对比措辞重要。
