# Notes

GB/T 41261 报警管理课程的教学工作笔记，供未来会话参考。

- **语言**：中文授课；技术术语保留英文并附中文（alarm、rationalization、shelving、deadband、flood）。
- **起点**（2026-09-30 确认）：自研上位机程序员（8 年 C#，工业设备场景，即 c#TDD 课程同一用户，见其 NOTES）。报警全是「看情况定义」，标准零基础。
- **动机与痛点**（AskUserQuestion 确认）：痛点四项全中——泛滥刷屏、定义随意、状态管理缺失、报警与操作脱节；目标选「完整改造模块」。课程轮流回应四个痛点，终点是 C# 模块改造落地。
- **模块形态**：自研上位机内的报警模块（非 WinCC/iFIX 等组态平台），代码示例统一 C#。
- **标准文本**：课程以国标 GB/T 41261-2022（= IEC 62682:2014，IDT）为「标准正文」与纲目；openstd 因版权不提供在线阅读，正文需购买（约 ¥70）。ISA-18.2/IEC 62682 仅作渊源一句话提及（用户 09-30 指定以国标为纲）。
- **网络**：WebFetch 被网络策略拦截；WebSearch 与 mcp web_reader 可用。RESOURCES.md 链接均经 WebSearch 核实存在。
- **产出节奏**：每课一个 HTML（lessons/）；共享 assets/style.css（自 c#TDD 复制改造，accent 换琥珀色）+ quiz.js（直接复制）+ triage.js（本课程新建：报警/事件/提示分类练习组件）。
- **打开课程**：`cmd.exe //c start "" "<lesson 的绝对路径>"`（explorer.exe 在此环境不可靠）。
- **课程路线图（拟）**：1 报警定义与三分类 → 2 生命周期与报警哲学文档 → 3 报警状态机 → 4 合理化与优先级矩阵 → 5 详细设计（死区/延时/分组/搁置）→ 6 KPI 与性能监测 → 7+ 自研模块改造落地（C# 设计，多课）。
- **与 c#TDD 课程联动**：同一用户；第 3 课「报警状态机」是绝佳 TDD 练习材料（TDD NOTES 里「报警条件判断」本就是答辩备选题）；改造落地课可回到 TddLab 式练习场。

- **进展**（09-30，第 5 课发布）：0005-detailed-design.html；assets 新增 deadband-lab.js（确定性信号 + 死区/延时交互实验室，seed=11，node 无头调参定版：默认 8 次/60s → 死区2℃剩3 → 延时2s剩2 → 组合仍2（剩的2次是真峰））。教学故事定为「治理终点不是零报警，是剩下的都是真报警；每个旋钮有盲区代价」。核实：颤抖=60s 内 ≥3 次转换（ISA-18.2，ChemRxiv 论文引证；180 条/时）；死区/延时具体数值标准不定死（工程决策记入 MADB）。铁律：触发延时 < MTR（延时吃响应窗）；死区 ≥ 噪声幅值。图表按 dataviz 技能规范：报警条红#b3261e vs 中性灰#d8d2c9 过 CVD 验证（ΔE 36.1），状态另有文字徽标兜底。新增参考卡 reference/deadband-tuning.html。作业=实验室压到 2 次并写盲区代价 + AlarmDefinition 加组态字段 + TDD HysteresisEvaluator（必含「死区带内真实越限被吞」用例）+ 盘点现场颤抖源。哲学文档/5 份 MADB 档案作业继续挂账未催。下一课：KPI 与性能监测（≤6 条/时、泛滥占比、驻留/陈旧报警、颤抖排行——事件历史库变体检中心）。
