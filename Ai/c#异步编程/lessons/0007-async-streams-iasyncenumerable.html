异步流：IAsyncEnumerable 前面都是「一个方法返回一个结果」。要「异步地逐条产出」——逐行读大文件、持续收设备数据——就用它。

← 上一课：IValueTaskSource

先看一个熟悉的同步写法

你肯定写过这个：

IEnumerable<int> GetNumbers()
{
    for (int i = 0; i < 10; i++)
        yield return i;      // 惰性、逐条产出
}

它不一次性返回整个集合，而是「要一条产一条」。异步流就是它的异步版——方法体里既能 await，又能 yield return。

异步流的写法

async IAsyncEnumerable<int> GenerateAsync()
{
    for (int i = 0; i < 10; i++)
    {
        await Task.Delay(100);   // 每条之间异步等待
        yield return i;          // 逐条产出
    }
}

// 消费：await foreach
await foreach (var item in GenerateAsync())
{
    Console.WriteLine(item);
}

核心是两件事：产出端用 async IAsyncEnumerable<T>，消费端用 await foreach。

为什么不直接返回 Task<List<T>>？

三个理由：

  • 内存：大集合要一次性全载入内存。异步流是「边产边消费」，内存只留当前一条。
  • 延迟：Task<List<T>> 必须等全部完成才能开始处理第一条；异步流拿到第一条就能开始。
  • 可无限、可中断：数据源可以无限（持续上报的设备），消费端随时 break 提前结束。

实战：逐行读大文件 + 取消

这个场景很常见，也贴合你的设备/文件处理：

async IAsyncEnumerable<string> ReadLinesAsync(
    string path,
    [EnumeratorCancellation] CancellationToken token = default)
{
    using var reader = new StreamReader(path);
    while (!reader.EndOfStream)
    {
        token.ThrowIfCancellationRequested();       // 检查点
        yield return await reader.ReadLineAsync(); // 逐行产出
    }
}

// 消费：UI 点「停止」时取消
await foreach (var line in ReadLinesAsync(path).WithCancellation(cts.Token))
{
    Process(line);
}

取消有两种传法，各有适用：

  • WithCancellation(token)：对任何来源的 IAsyncEnumerable 都有效。
  • [EnumeratorCancellation] 参数：方法自己接收 token，不「烧死」在某一次枚举上，可多次枚举传不同 token。

贴合你的场景：设备数据流

你之前问的串口/激光器场景，就可以把「设备持续上报」封装成异步流：

async IAsyncEnumerable<string> ReadDeviceFramesAsync(CancellationToken token = default)
{
    while (!token.IsCancellationRequested)
    {
        string frame = await ReadNextFrameAsync(token);  // 收一帧（真异步读，或专用读线程）
        yield return frame;                              // 抛给消费端
    }
}

// UI 端：
await foreach (var frame in ReadDeviceFramesAsync(cts.Token))
{
    UpdateDisplay(frame);   // 一帧一帧刷新
}

注意：底层「收一帧」如果走的是你之前那条阻塞串口，得用第 5 课那套（真异步 BaseStream 或专用读线程 + Channel）来接，别在异步流里直接阻塞。

底层：它还是那个状态机

呼应第 2 课——async IAsyncEnumerable<T> 方法同样被编译成状态机，枚举器的 MoveNextAsync() 返回 ValueTask<bool>（呼应第 5/6 课：用 ValueTask 省分配）。

public interface IAsyncEnumerable<out T>
{
    IAsyncEnumerator<T> GetAsyncEnumerator(CancellationToken ct = default);
}

public interface IAsyncEnumerator<out T> : IAsyncDisposable
{
    ValueTask<bool> MoveNextAsync();   // 返回「还有没有下一条」
    T Current { get; }
}
注意 同一个枚举器的 MoveNextAsync 不能并发调用，DisposeAsync 也不能在它进行中调用。await foreach 天然遵守这些规则，但手动调 MoveNextAsync（比如套超时）时容易踩坑。
