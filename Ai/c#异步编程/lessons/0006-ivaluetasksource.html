先说清楚 这是最硬核的一课。诚实讲：绝大多数人一辈子都不会自己实现 IValueTaskSource。但读懂它，你就真正理解了 .NET 高性能异步的地基——那些「零分配」「池化」不再是玄学。

ValueTask 的第三种形态

上一课说 ValueTask 同步完成零分配、异步完成要包 Task。但 ValueTask 内部其实是一个判别联合，可能是三种东西之一：

  • TResult —— 同步结果，零分配。
  • Task<T> —— 异步完成时的传统 Task。
  • IValueTaskSource<T> —— 第三种：对象自己就是「结果 + 调度器」。

第三种形态，就是「异步完成也零分配」的关键。做法是：对象复用（池化），每次操作不 new Task，而是让一个可复用的对象自己负责「完成时通知续延」。

IValueTaskSource 接口长什么样

public interface IValueTaskSource<out TResult>
{
    ValueTaskSourceStatus GetStatus(short token);
    TResult GetResult(short token);
    void OnCompleted(Action<object> continuation, object state,
                     short token, ValueTaskSourceOnCompletedFlags flags);
}

三个方法，职责分明：

  • OnCompleted：登记续延——await 时，编译器就是调它把「后面那段」挂上去。
  • GetResult：完成时取结果（出错就抛异常）。
  • GetStatus：查状态（Pending / Succeeded / Faulted / Canceled）。

注意那个 short token——它是版本号。因为对象被池化复用，同一个对象可能先后服务很多次操作；token 用来区分「这次返回的 ValueTask 对应的是第几次」。旧 ValueTask 拿旧 token 去取结果，会得到 InvalidOperationException，而不是错拿别人的结果。

最小例子：用现成的样板

手写 IValueTaskSource 很繁琐，但 .NET 提供了一个现成的样板结构体 ManualResetValueTaskSourceCore<T>（在 System.Threading.Tasks.Sources 命名空间）。你只需要转发三个方法：

using System.Threading.Tasks.Sources;

class PooledAsyncOp : IValueTaskSource<int>
{
    private ManualResetValueTaskSourceCore<int> _core;

    public ValueTask<int> RunAsync()
    {
        _core.Reset();                          // 复用前复位，版本号 +1
        QueueWork(() => _core.SetResult(42));   // 真正的工作，完成时设结果
        return new ValueTask<int>(this, _core.Version);  // 用当前版本号包起来
    }

    // 下面三行是纯样板，直接转发给 _core
    public int GetResult(short token) => _core.GetResult(token);
    public ValueTaskSourceStatus GetStatus(short token) => _core.GetStatus(token);
    public void OnCompleted(Action<object> continuation, object state, short token,
                            ValueTaskSourceOnCompletedFlags flags)
        => _core.OnCompleted(continuation, state, token, flags);
}

关键点：

  • Reset() 让 Version 自增——这是 token 的来源。
  • RunAsync() 每次返回 new ValueTask<int>(this, version)，不分配任何堆对象（ValueTask 是结构体，this 就是池里的对象）。
  • 续延由 _core 统一管理，完成时它负责调度。

谁在用 IValueTaskSource

它不是给你我日常写业务用的，是给基础设施用的：

  • Channel<T> 的 ReadAsync —— 返回 ValueTask，内部用池化的 IValueTaskSource，生产者-消费者流水线零分配。
  • Socket 的新 API（.NET 6+）—— 高频网络收发零分配。
  • Stream.ReadAsync(Memory<byte>)、System.IO.Pipelines —— 高性能 I/O 管线。

这些「快」的背后，就是这套机制：不 new Task，复用对象自己当调度器。

那你什么时候才需要自己写？

结论 几乎用不上。写业务、写 UI、写驱动，Task 就是正确默认；热路径测量出分配压力，先试 ValueTask；只有你在写「给几千人复用、要高吞吐零分配」的基础库时，才轮到 IValueTaskSource。看懂它，是为了读懂 Channel/Socket/Pipelines 的底层，而不是为了亲手写它。
