Lesson 0001 · 心智模型

async 不是多线程 await 是「注册续延」，不是「开新线程等结果」。这是理解一切异步的承重墙。

先回答一个反直觉的问题

你写了八年 await。那么——

提问 var html = await client.GetStringAsync(url); 这行代码在等网络返回的那几百毫秒里，有没有一个线程在替你「等」？

答案是：没有。 对真正的异步 I/O 来说，等待期间没有任何线程被占用。这正是 async 与「多线程」最反直觉、也最容易被误解的地方。

为什么会有 async/await

先看问题。同步 I/O 是这样的：

byte[] data = File.ReadAllBytes(path);  // 线程在这里空转，等磁盘

读文件时，线程什么也不干，就在那儿等。线程很贵：每个线程默认占约 1 MB 栈内存，线程池有上限，线程间切换（上下文切换）有开销。

如果 1000 个客户端同时请求，每个都用一个线程空等 I/O，就需要 1000 个线程 —— 内存和调度很快会崩溃。

于是历史上一路演化出几个答案：

  • APM（BeginRead/EndRead + IAsyncResult）：显式回调，能用但组合起来是「回调地狱」。
  • EAP（事件式 XxxAsync/XxxCompleted）：略好，但仍啰嗦。
  • TPL（.NET 4 的 Task）：统一了「任务」概念，但要手写 ContinueWith。
  • async/await（C# 5）：让编译器替你写那些回调。

所以 async/await 不是新魔法，它本质是：把「回调」这件事，用看起来像同步代码的语法写出来。

核心心智模型：await = 注册续延

看一段代码，注意注释：

async Task<string> FetchAsync()
{
    // ① 发起异步请求，立刻拿到一个 Task（还没结果）
    var task = client.GetStringAsync(url);

    // ② await：把「后面这段」登记成续延，然后立刻返回控制权
    var html = await task;   // ← 方法在这里「挂起」，线程被释放

    // ③ 续延：将来某个线程池线程会从这里继续
    return html;
}

关键点：

  • await 不阻塞。它把「await 之后的代码」打包成一段回调（叫续延），登记到那个 Task 上，然后方法立刻返回。
  • 所以 async 方法在 await 处「返回」了，但方法还没完成——它只是把控制权交还了调用方。
  • 将来 Task 完成时，这段续延才会被调度去执行（通常跑在一个线程池线程上）。

两种 Task，别混淆

Stephen Cleary 有一个极有用的区分：

核心区分
  • 委托任务（Delegate Task）：Task.Run(() => ...) 返回的。它代表「有一段代码要去执行」，需要占用一个线程。
  • 承诺任务（Promise Task）：async 方法返回的 Task。它只代表「完成的通知」，自己没有线程。

async/await 主要打交道的是承诺任务。而「没有线程」这个真相，正发生在承诺任务等待真正异步 I/O 的那一刻。
