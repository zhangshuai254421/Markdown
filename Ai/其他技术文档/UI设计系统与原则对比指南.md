# UI 设计系统与原则对比指南

> 三大设计体系：Google Material Design、Apple HIG、尼尔森十大可用性原则 —— 分别代表 **规范体系**、**平台哲学** 和 **通用法则**。

---

## 一、Google Material Design

### 概述

Material Design 是 Google 于 2014 年发布的跨平台设计系统，最新版本为 **Material Design 3（Material You）**。其核心隐喻来自**纸张与墨水**——将 UI 视为有物理属性的"数字纸张"。

> 官网：[material.io](https://material.io)

### 核心设计理念

```
┌──────────────────────────────────────┐
│           Material Design            │
├──────────────────────────────────────┤
│  纸张隐喻  │  大胆用色  │  明确动效  │
│  (Surface) │  (Color)  │  (Motion)  │
├────────────┴───────────┴────────────┤
│       层次感 · 响应性 · 一致性       │
└──────────────────────────────────────┘
```

### 三大核心原则

| 原则 | 说明 |
|---|---|
| **Material 是隐喻** | UI 元素模拟纸张和墨水——表面、边缘、阴影都基于物理世界，但突破了物理限制（如无限缩放） |
| **大胆、图形化、有目的性** | 色彩鲜明、排版有层次、留白充裕，用视觉设计引导注意力 |
| **运动赋予意义** | 动效不是装饰，而是反馈操作、引导焦点、表达空间关系 |

### Material Design 3（Material You）新特性

| 特性 | 说明 |
|---|---|
| **动态取色** | 从壁纸自动提取主色调，生成完整的调色板 |
| **Tonal Palette** | 放弃 50-900 色阶标号，改为 Tonal 调色系统 |
| **自适应布局** | 同一组件在不同屏幕尺寸上形态自适应 |
| **Shape 简化** | 默认更圆角，减少切割感 |
| **M3 Token 体系** | 用 Design Token 统一管理颜色、字体、形状 |

### M3 核心组件速查

| 类别 | 组件 |
|---|---|
| **布局** | Top App Bar、Bottom App Bar、Navigation Rail、Navigation Drawer、Navigation Bar |
| **按钮** | FAB（悬浮按钮）、Extended FAB、Filled Button、Outlined Button、Text Button、Icon Button |
| **输入** | Text Field（Filled/Outlined）、Checkbox、Radio、Switch、Slider、Date Picker、Time Picker |
| **展示** | Card、List、Chip、Badge、Tooltip、Divider |
| **反馈** | Snackbar、Dialog、Bottom Sheet、Progress Indicator |
| **导航** | Tabs、Stepper、Search |

### 典型规范细节

```text
FAB（悬浮操作按钮）:
  - 尺寸: 56dp（默认）/ 40dp（小）/ 96dp（大）
  - 圆角: 16dp（默认）/ 12dp（小）/ 28dp（大）
  - 阴影: 6dp 高度
  - 位置: 距屏幕边缘 ≥ 16dp

Card（卡片）:
  - 圆角: 12dp
  - 阴影: Elevation 1dp-8dp
  - 内边距: 16dp (M3)
  - 描边: outline variant 替代阴影区分

Top App Bar:
  - 高度: 64dp
  - 标题字号: 22sp (M3) / 20sp (M2)
  - 滚动行为: 可收缩 / 固定
```

## 二、Apple Human Interface Guidelines（HIG）

### 概述

Apple HIG 是 Apple 的官方设计规范，覆盖 iOS、macOS、watchOS、tvOS 和 visionOS。核心哲学：**设计服务于用户体验，而非视觉炫技**。

> 官网：[developer.apple.com/design](https://developer.apple.com/design)

### 核心设计理念

```
┌─────────────────────────────────────────────────┐
│              Apple HIG                           │
├─────────────────────────────────────────────────┤
│  清晰度       │   遵从性      │   深度           │
│  (Clarity)    │ (Deference)  │  (Depth)         │
├───────────────┴──────────────┴──────────────────┤
│      少即是多 · 平台原生感 · 无障碍优先          │
└─────────────────────────────────────────────────┘
```

### 六大设计原则

| 原则 | 说明 |
|---|---|
| **清晰（Clarity）** | 文字清晰可读、图标精确表意、装饰恰到好处。以内容为中心 |
| **遵从（Deference）** | UI 帮助用户理解内容，但不与之竞争。毛玻璃效果让控件"退后" |
| **深度（Depth）** | 视觉层次和逼真的动效传达层级关系，让用户知道自己在哪 |
| **一致性（Consistency）** | 使用系统标准控件和熟悉的交互模式 |
| **直接操控（Direct Manipulation）** | 手势直接作用于屏幕上，如拖拽、旋转、捏合 |
| **反馈（Feedback）** | 每次交互都有即时视觉反馈 |

### 跨平台适配要点

| 平台 | 核心输入 | 设计特征 |
|---|---|---|
| **iOS** | 触摸（多点触控） | 44pt 最小触控目标，底部导航，边缘滑动手势 |
| **iPadOS** | 触摸 + 键盘 + 触控板 | 分屏/侧拉，多窗口，台前调度 |
| **macOS** | 鼠标 + 键盘 | 菜单栏，窗口控制，右键菜单，拖放 |
| **watchOS** | 触摸 + 数码表冠 | 黑色背景节省电量，列表式/蜂窝式导航 |
| **tvOS** | 遥控器/Siri | 焦点系统，3D 倾斜视差效果 |
| **visionOS** | 眼动 + 手势 | 空间 UI，玻璃材质，凝视交互 |

### 关键规范速查

```text
触控目标（iOS）:
  - 最小尺寸: 44×44 pt（推荐）
  - 间距: 元素间 ≥ 8pt 避免误触

导航栏:
  - 高度: 44pt（iPhone 竖屏）/ 32pt（iPhone 横屏）
  - 大标题: 52pt（可折叠）

间距与边距:
  - 边距: 16pt（iPhone）/ 20pt（iPad）
  - Safe Area 底部: ≥ 34pt（iPhone X+）

字体:
  - SF Pro（系统字体）- 9种字重，可变间距
  - 尺寸规范: 标题 34pt / 标题2 22pt / 正文 17pt / 说明 13pt

颜色:
  - 系统颜色自动适配深色/浅色模式
  - Accent Color 统一交互元素色彩
  - SF Symbols: 6000+ 系统图标，9 种字重可调

毛玻璃（Blur）:
  - Regular: 工具栏/Navigation Bar
  - Prominent: 背景模糊
  - 深色/浅色自动适配
```

### Material Design vs Apple HIG 关键差异

| 维度 | Material Design | Apple HIG |
|---|---|---|
| **阴影表达层级** | ✅ 核心手段（Elevation） | ❌ 极少使用，改用毛玻璃 |
| **导航模式** | Navigation Drawer + Bottom Nav | Tab Bar + 侧滑返回 |
| **FAB 悬浮按钮** | ✅ 标志性组件 | ❌ 不推荐，用 Toolbar 按钮 |
| **返回交互** | 左上角箭头 / 系统返回键 | 左侧边缘右滑 + 左上角按钮 |
| **系统字体** | Roboto / Google Sans | SF Pro / SF Mono / New York |
| **设计语言** | 纸张卡片化，色彩丰富 | 毛玻璃层次，低调精致 |
| **开关组件** | 圆形滑块 | 椭圆形，绿色底色 |
| **对话框按钮** | 右对齐（"取消"在左） | 居中或右对齐（"取消"常在上方） |

## 三、尼尔森十大可用性原则

### 概述

由可用性之父 **Jakob Nielsen** 于 1994 年提出，是 UI/UX 领域最经典的**通用评估法则**。它不是具体的设计规范，而是一套**可以评判任何界面的启发式原则**。

### 十大原则详解

#### 1. 系统状态可见性（Visibility of System Status）

> **系统应始终在合理时间内通过适当的反馈让用户了解当前状态。**

| 场景 | 示例 |
|---|---|
| 加载中 | 进度条、骨架屏、旋转指示器 |
| 操作确认 | "已保存"提示、发送成功✅ |
| 位置感知 | 面包屑导航、步骤条（步骤 2/4） |

```text
❌ 差：点击"支付"后页面没有任何反应
✅ 好：按钮变灰 + 显示转圈 + "正在处理..."
```

#### 2. 系统与真实世界的匹配（Match between System and the Real World）

> **使用用户熟悉的语言，遵循现实世界的约定，信息以自然、逻辑的顺序呈现。**

| 场景 | 示例 |
|---|---|
| 图标隐喻 | 垃圾桶=删除、🏠=首页、信封=邮件 |
| 文案表达 | "加入购物车"而非"添加至项目队列" |
| 日期格式 | 在中国显示"2024年1月15日"而非"01/15/2024" |

#### 3. 用户控制与自由（User Control and Freedom）

> **用户经常误操作，需要清晰的"紧急出口"来撤销。**

| 场景 | 示例 |
|---|---|
| 撤销操作 | Gmail "撤销发送"（5秒窗口） |
| 返回上一步 | 返回按钮、取消按钮 |
| 退出流程 | 多步骤表单中的"保存草稿并退出" |

#### 4. 一致性与标准（Consistency and Standards）

> **不要让用户猜测不同的词语、情境或操作是否意味着相同的事情。**

| 维度 | 示例 |
|---|---|
| **内部一致** | 应用内同一功能用相同图标和文字 |
| **外部一致** | 用红色表示删除/危险（平台约定） |
| **命名一致** | "编辑"不叫"修改"，全程统一 |

```text
❌ 差：这个页面叫"我的订单"，另一个页面叫"订单中心"
✅ 好：统一叫"我的订单"
```

#### 5. 防错原则（Error Prevention）

> **最好的错误消息是没有错误消息。提前消除容易出错的条件。**

| 场景 | 技术手段 |
|---|---|
| 表单约束 | 日期选择器（防非法格式）、输入掩码 |
| 危险确认 | 删除前弹出确认对话框 |
| 灰度禁用 | 不满足条件时按钮置灰，不可点击 |
| 智能默认 | 预选最常见选项 |

#### 6. 识别而非回忆（Recognition rather than Recall）

> **将选项、对象和操作可见化，降低用户的记忆负担。**

| 场景 | 示例 |
|---|---|
| 搜索历史 | 显示最近搜索的关键词 |
| 表单填写 | 输入时自动补全建议 |
| 导航 | 始终可见的菜单，而非隐藏的汉堡菜单 |
| 密码 | "显示密码"👁️按钮 |

```text
❌ 差：用户必须记住订单号才能查询
✅ 好：在订单列表页展示所有订单，点击进入详情
```

#### 7. 使用的灵活性与效率（Flexibility and Efficiency of Use）

> **同时满足新手与专家用户，允许用户定制常用操作。**

| 场景 | 示例 |
|---|---|
| 快捷键 | Ctrl+S 保存、Ctrl+Z 撤销 |
| 快捷操作 | 长按弹出快捷菜单 |
| 自定义 | 工具栏自定义、常用联系人置顶 |
| 批量操作 | 多选 → 批量删除/标记已读 |

#### 8. 美观简约的设计（Aesthetic and Minimalist Design）

> **界面不应该包含不相关或极少需要的信息。每多一个元素都会分散注意力。**

| 原则 | 说明 |
|---|---|
| **内容优先** | 只展示必要的信息和操作 |
| **渐进披露** | 高级选项默认折叠，需要时展开 |
| **信息层级** | 重要信息大、醒目；次要信息小、低对比度 |
| **留白** | 充足的留白让内容"呼吸" |

```text
❌ 差：注册页 15 个必填字段
✅ 好：只问邮箱+密码，其余注册后补充
```

#### 9. 帮助用户识别、诊断并恢复错误（Help Users Recognize, Diagnose, and Recover from Errors）

> **错误消息用平实的语言准确描述问题，并建设性地提出解决方案。**

| 要素 | 示例 |
|---|---|
| **讲人话** | ❌ "Error 403: Forbidden" → ✅ "您没有权限访问此页面" |
| **解释原因** | "密码长度至少 8 位，且需包含数字和字母" |
| **提供出路** | "用户名已被注册，[去登录？] [找回密码？]" |

#### 10. 帮助与文档（Help and Documentation）

> **最好的系统不需要文档，但有时仍需提供帮助。帮助应当易于搜索、聚焦任务、步骤简洁。**

| 形式 | 示例 |
|---|---|
| **即时提示** | 输入框旁的 ❓Tooltip |
| **引导式教学** | 首次使用时逐步引导 + "跳过"按钮 |
| **搜索式帮助** | 帮助中心的关键词搜索 |
| **上下文帮助** | 当前页面的"帮助"按钮跳转到对应章节 |

## 四、三大体系对比总结

| 维度 | Material Design | Apple HIG | 尼尔森十原则 |
|---|---|---|---|
| **性质** | 跨平台设计系统 | 平台设计规范 | 通用评估法则 |
| **覆盖面** | Android / Web / iOS / Flutter | iOS / macOS / watchOS / tvOS / visionOS | 任何界面（软件/网站/硬件） |
| **核心隐喻** | 纸张 + 墨水（物理感） | 内容至上（毛玻璃退后） | 人因工程（认知负荷） |
| **强调重点** | 动效设计、色彩体系 | 平台原生、触控手势 | 错误预防、用户控制 |
| **风格导向** | 大胆用色、卡片化 | 克制精致、透明层次 | 无特定风格 |
| **适用场景** | 选择跨平台规范 | 开发 Apple 平台 App | 评审任何产品体验 |

### 实践建议

```text
项目启动阶段:
  ├── 用 尼尔森十原则 做设计评审清单
  ├── 选定平台规范（Android → Material / iOS → HIG）
  └── 跨平台项目以 Material Design 为基准做适配

设计阶段:
  ├── 结构布局 → 参考 HIG 导航模式
  ├── 视觉风格 → 参考 Material 色彩+圆角规范
  └── 交互校验 → 逐一对照尼尔森十原则自检

评审阶段:
  ├── 十原则逐个打分（1-5 分）
  ├── 找出最薄弱的 2-3 项优先改进
  └── 重点审查「防错」和「错误恢复」
```
