在掘金量化跑通第一个 C# 回测

今天回到你的主场：写 C#。目标是一个 40 分钟内可完成的闭环（不含终端下载安装）——在掘金量化（MyQuant）的 C# SDK 上跑通一次真实 A 股历史数据的回测，并读懂它的成绩单。更深一层的目标是建立一个贯穿全课程的工程直觉：策略是一个类，回测是一个测试。

事件驱动：掘金怎么调用你的代码

你平时写的程序大多是 Main() 起头、你控制流程。掘金的策略框架相反——引擎掌握控制权，你的代码被动响应。一个策略只需要实现两个回调方法：

方法调用时机你在里面做什么
OnInit()回测开始前，恰好一次声明订阅什么标的、什么频率；初始化状态
OnBar(Bar bar)每来一根 K 线调用一次（日线上=每个交易日一次）读当前行情，决定：买、卖、还是不动

Bar 是"当前这一根 K 线"——包含 symbol、open/high/low/close/volume 等字段。官方文档见 C# SDK 快速开始 与 策略基类。

TDD 类比（你刚在 TddLab 里练过的东西）：Strategy 子类是被测对象；掘金引擎是测试运行器；历史数据是测试输入；最后那份回测报告是测试报告。区别只有一个：策略这个"测试"断言的不是代码正确性，而是"这套规则在历史上是否产生正期望"。

回测五要素，映射到掘金

上一课的五要素（第 1 课），在掘金里各就各位：

要素第 1 课模拟器掘金量化
1. 数据合成行情终端内置 A 股历史数据（基础版免费投研数据）
2. 信号规则JS 里的双均线你写的 OnBar
3. 执行假设收盘价成交回测撮合（默认按下一根 K 线开盘价成交；回测参数说明）
4. 交易成本手动选 0 / 0.1% / 0.3%佣金/滑点要在 SetBacktestConfig 或终端"回测参数"里显式设置（签名与默认值）
5. 绩效统计四个指标瓦片回测报告：累计收益率、年化、夏普、最大回撤、胜率……

注意第 4 行，这是本课最重要的坑：掘金 C# 的 SetBacktestConfig 签名里，佣金和滑点的默认值是 0。不显式设置，引擎会给你一份"零成本"的漂亮报告——第 1 课你手动调滑块体会到的"成本放血"，在这里必须由你亲手写进参数。买入持有只交易一次，费用影响小；第 3 课双均线交易多次，成本才开始咬人。

动手：三个 10 分钟（终端已装好）

准备：装终端：在 myquant.cn 下载并安装掘金量化终端（目前是 Windows 版，正好你的环境），登录。下载安装不计入下面的 10 分钟。

第一个 10 分钟——建策略、拿两把钥匙：① 量化研究 → 新建策略 → 选 C#，记住生成的策略 ID；② 右上角头像 → 系统设置 → 密钥管理，复制 token。然后用 Visual Studio 打开终端生成的 .sln 工程——C# 策略用 VS 写，终端内置编辑器主要服务 Python。

第一次编译若报 BadImageFormatException，多半是 SDK 位数（x86/x64）和项目平台目标不一致——把两者统一即可；如果还卡住，把报错贴给老师。

第二个 10 分钟——跑通"买入持有"。策略类和入口分两个文件写。先替换策略类：

BuyAndHold.cs — 2016-2025 持有沪深300ETF（95% 仓位）

using GMSDK;

public class BuyAndHold : Strategy
{
    private const string Symbol = "SHSE.510300"; // 沪深300ETF
    private bool _bought;                        // 仓位状态标志：后面会变成真正的状态机

    public BuyAndHold(string token, string strategyId, StrategyMode mode)
        : base(token, strategyId, mode) { }

    public override void OnInit()
    {
        Subscribe(Symbol, "1d");                 // 订阅日线
    }

    public override void OnBar(Bar bar)
    {
        if (!_bought)
        {
            OrderTargetPercent(Symbol, 0.95,      // 目标仓位：95%（留 5% 现金付手续费）
                PositionSide.PositionSide_Long,
                OrderType.OrderType_Market);
            _bought = true;
        }
        // 之后再无动作：这就是"买入持有"
    }
}

再写回测入口（如果你用的是终端生成的模板，Program.cs 里已经有 Main，把内容替换成下面这样）：

Program.cs — 设置回测参数并启动

using System;
using GMSDK;

class Program
{
    static void Main()
    {
        string token = "你的 token";        // 系统设置 → 密钥管理
        string strategyId = "你的策略 ID";  // 新建 C# 策略时生成

        var s = new BuyAndHold(token, strategyId, StrategyMode.MODE_BACKTEST);

        // 起止时间、初始资金、成交比例、佣金、滑点、复权
        s.SetBacktestConfig("2016-01-01 09:30:00", "2025-12-31 15:00:00",
                            100000, 1, 0.0003, 0.001, Adjust.ADJUST_PREV);

        Console.WriteLine("回测返回码: " + s.Run()); // 0 = 成功
    }
}

佣金 0.0003 = 万 3；滑点 0.001 = 0.1%；Adjust.ADJUST_PREV = 前复权（第 5 课细讲）。为什么目标仓位是 95% 而不是 100%？因为 100% 会把现金全押上，手续费一来就"资金不足"被拒单——留 5% 现金是实盘习惯。函数签名以你本地 SDK 的 IntelliSense 为准；如果你的版本只接受前三个参数，就用三参数版本，再在终端"回测参数"里设置佣金/滑点。按 F5 运行，掘金终端保持登录；回测结束后到 策略研究 → 绩效 看报告。

这里为了聚焦状态机，下单后直接把 _bought 置为 true，默认委托会成交。真实策略应通过 OnOrderStatus 或 GetOrder 确认成交后再改状态——第 12 课模拟盘会再提醒你。

第三个 10 分钟——读成绩单，再做三次手术：

  1. 读四个数：累计收益率、年化收益率、最大回撤、夏普比率。对照 术语表确认每个数的含义。
  2. 换标的：把 SHSE.510300 全部改成 SHSE.600000（浦发银行），重跑。记下两个数字：年化变了多少？回撤变了多少？
  3. 减半仓位：把 OrderTargetPercent(Symbol, 0.95, ...) 的 0.95 改成 0.5，重跑。年化和回撤各怎么变？一半资金"睡大觉"的代价与好处，现在就在你眼前量化出来了。

本课的工程直觉，现在该长出来了：策略 = 一个实现了两个回调方法的类；改策略 = 改类；验证策略 = 跑测试看报告。作者观点这个心智模型比"量化很高深"的说法重要一百倍——它把量化还原成你每天都在做的工程活动。

三个诚实声明

声明一：这是 A 股数据，但"平台能回测"不等于"策略符合 A 股物理"。掘金的 A 股回测通常替你处理了 T+1、涨跌停、停牌等规则（以平台当期文档为准）；第 7-8 课你会亲手实现这些规则，再回来对照掘金的报告——那时你才有能力问出"它到底怎么处理涨跌停和印花税"。

声明二：成本参数是你自己设的。掘金 C# 的 SetBacktestConfig 默认佣金/滑点为 0；不显式设置，报告就是"零成本乌托邦"。第 1 课的教训在这里第一次落地：先检查成本假设，再看收益曲线。

声明三：买入持有不是策略，是基准。术语表里"基准"那条说过：跑不赢基准的复杂策略没有存在意义——今天你亲手制造的，就是那个"用来被打败的参照物"。它会被第 3 课的双均线正式挑战一次，然后在第 6 课被重新平反一次。
